Airbnb data in Power BI: load a listings CSV into Power BI Desktop (free)

Published 2026-09-10. Source: Inside Airbnb, CC BY 4.0. Data Vault is not affiliated with Airbnb, Inside Airbnb, or Microsoft.

Honesty note: the python prep below was executed against the shipped sample file with pandas 3.0.5, and its output is copied verbatim. The Power BI steps follow menus as documented on learn.microsoft.com (the Power Query Text/CSV connector page and the Power Query data types page, both checked live 2026-09-10); no Power BI Desktop install ran on this build box, so there are no screenshots and the in-app steps are untested-in-app.

Power BI Desktop is the free tier of Power BI, and it opens CSV files through the Text/CSV connector in Get data. The connector auto-detects column types by inspecting the first 200 rows, and on an Airbnb listings file that automatic pass is where the damage starts: a 19-digit listing ID lands as a number, the ZIP-code column lands as a number, and both survive only until a join, a sort, or a snapshot with different values says otherwise. Cast those two to text in Power Query and the import stays boring.

The schema is 12 columns shared by all six cities in the pack: id, name, neighbourhood, latitude, longitude, room_type, price, minimum_nights, availability_365, number_of_reviews, reviews_per_month, last_review. The Airbnb data guide explains each one.

Prep the CSV before Power BI touches it

Microsoft documents two number types that matter here. Decimal Number is a 64-bit float with at most 15 digits of precision, and Whole Number is a 64-bit integer that tops out at 9,223,372,036,854,775,807. The 19-digit sample ID 1690760048869752293 is already past the float's 15-digit exact range, so any auto-detected numeric type is playing with fire, and Whole Number only clears it with about 10x of ceiling to spare. The text cast ends the guessing: joins and dedupes on exact strings cannot lose a digit, ZIP codes keep any leading zero, and no future snapshot can break a refresh by pushing an ID past a numeric ceiling.

This is the whole prep, executed against the shipped sample. It was run with pandas 3.0.5 and the output below is verbatim:

import pandas as pd

df = pd.read_csv("sample.csv")

# 19-digit listing IDs: join as text, never as a float
df["id"] = df["id"].astype("string")
# ZIP codes are labels, not numbers; text keeps any leading zero intact
df["neighbourhood"] = df["neighbourhood"].astype("string")
df["room_type"] = df["room_type"].astype("string")
df["reviews_per_month"] = df["reviews_per_month"].fillna(0).astype("float64")
df["last_review"] = pd.to_datetime(df["last_review"], errors="coerce")

df.to_csv("sample-powerbi.csv", index=False)
print(df.shape)
print(df.dtypes.to_string())

What each line buys you in Power BI: the id and neighbourhood casts make both fields text, so the Changed type step Power Query adds on import cannot turn them into numbers. room_type as text gives clean slicer values. Filling reviews_per_month with 0 handles the 4 rows in 20 that have no reviews, so a card on that column reads 0 instead of blank. The date parse turns last_review into ISO dates Power Query reads as Date. The 4 date-null rows stay null on purpose: a listing with no reviews has no review date, and 0 would be a lie.

Run the same script against any full-pack city CSV before importing; nothing in it is sample-specific.

The CSV import, step by step

  1. Open Power BI Desktop (free download from Microsoft; it works without a license or account for local files). On the Home tab pick Get data, then Text/CSV, and select the cleaned CSV. Microsoft's connector doc documents this exact path.
  2. The preview window shows the first rows plus three dropdowns: File Origin (leave 65001: Unicode UTF-8; this CSV is UTF-8), Delimiter (comma), and Data Type Detection (leave Based on first 200 rows; the doc warns the entire-dataset option slows the initial load).
  3. Pick Transform Data, not Load. That opens the Power Query editor instead of dumping the auto-detected types straight into the model.
  4. In the editor, check Applied Steps. You will see Promoted Headers and Changed Type, the two steps auto-detection adds when it is on. Select the id and neighbourhood columns (Ctrl-click both) and set their type to Text from the Data type dropdown on the Home tab. Confirm price reads Decimal Number and last_review reads Date.
  5. Optional quick test: Home, Keep Rows, Keep Top Rows, 20. Power Query keeps the first 20 rows everywhere downstream, which makes the first Close & Apply instant. Right-click the step in Applied Steps and delete it when you want the full file back.
  6. Close & Apply. The data lands in the model, and the Table view shows all 12 columns; 20 rows for the sample, 11,295 for Austin, 90,169 for the whole pack across city files.

The one measure to add first

Switch to Report view, pick New measure from the Home or Modeling tab, and type:

Average price = AVERAGE('sample-powerbi'[price])

Microsoft's DAX reference documents AVERAGE as the arithmetic mean of a column, with two behaviors worth knowing before you trust it: cells containing zero are counted, empty cells are skipped, and a measure over zero rows returns blank. Drop the measure on a Card visual and the sample shows 321.05 dollars. Add MEDIAN('sample-powerbi'[price]) as a second measure and it shows 220.00 dollars. The 101-dollar gap is the luxury tail: one 1,230.67-dollar listing pulls the mean while leaving the median alone. The price data page documents the same skew at city scale, where San Diego's mean runs 483.80 against a median of 322.92. Slice by room_type and the sample splits into Entire home/apt at 372.11 (16 rows) and Private room at 116.80 (4 rows).

Three viz ideas that work on this schema

1. Price map

Put longitude and latitude on a map visual, Average price on the size or color field, room_type in the Filters pane. The sample gives 20 Austin points; the full pack gives all six cities in one view. Expect a handful of dark dots to dominate: the same top-of-market listings that skew the mean show up as the darkest circles, so bin price or filter the top tail before comparing neighborhoods.

2. Room-type bar with the two means

A clustered bar chart: room_type on the axis, Average price and a median measure as values. The two bars per type make the skew visible without a footnote. On the sample the entire-home pair reads 372.11 against 271.80, and the private-room pair 116.80 against 111.59; the wider the gap, the more that segment's average is being pulled by its top listings.

3. Availability histogram

Right-click availability_365 in the Fields pane, choose New group, and set a 30-night bin size. Put the binned field on a column chart axis and count of rows as the value. In the 20-row sample the median is 285 open nights and half the listings show 300 or more, which is what open calendars with light bookings look like; the bars under 30 nights are where bookings and host blocks pile up. Rebuild it per city file and the market differences read straight off the shapes.

Gotchas

  • Locale and the decimal comma. Power Query on the desktop interprets values using your operating system regional format, per Microsoft's data types documentation. A US-format CSV like this one (prices 61.00, 149.00) fails or misreads when Windows is set to a European region where the comma is the decimal separator; the same trap bites in reverse if you load a European-exported CSV on a US machine, where 61,50 arrives as text and the Changed type step fills the column with errors. The fix Microsoft documents: right-click the column heading, Change type, Using locale, and pick the locale the file was written in. For a whole-file override, open the options window and set Current file, Regional settings.
  • Snapshot bias. Every file is one scrape on one date: Austin 2026-06-22 through New York City 2026-08-10, a 49-day spread across peak season. A Power BI report built on these numbers describes those days, and no DAX function fixes that. The methodology page covers what a one-day capture can and cannot support.
  • ID precision ceiling. Decimal Number holds 15 digits exactly, Whole Number holds integers to 9,223,372,036,854,775,807, and today's pack fits under both ceilings. Cast id to Text anyway; if a join or dedupe misfires, check whether both sides treat it as text.
  • Nulls in review fields. Listings with zero reviews have empty reviews_per_month and last_review; 4 of the 20 sample rows. Fill the rate with 0, leave the date null, and remember AVERAGE skips the blanks.

FAQ

How do I import an Airbnb CSV into Power BI?

Power BI Desktop is free. Pick Get data, then Text/CSV, and open the CSV. The preview window shows the first rows; pick Transform Data instead of Load so you land in the Power Query editor. Two columns need fixing before anything loads: the listing ID and the ZIP-code column should be text, not numbers. Then Close & Apply. The free 20-row sample on this page runs through the whole flow if you want a dry run first.

Why do my prices turn into errors or wrong values in Power Query?

Locale. Power Query on the desktop interprets numbers using your operating system regional format. On a machine set to a European region, the decimal separator is a comma, so a US-style value like 61.00 either fails the conversion to decimal or comes out misread. Right-click the column heading, choose Change type, then Using locale, and pick English (United States) for a US-format CSV. You can also override the locale for the whole file under Current file, Regional settings in the options window.

What does the DAX AVERAGE function do with blank prices?

It ignores them. Microsoft documents that AVERAGE counts cells containing zero but skips empty cells, so a blank price drops out of both the sum and the divisor. With no rows to aggregate the measure returns blank rather than zero. On the 20-row sample every listing has a price, so the measure returns 321.05 dollars, against a median of 220.00; the gap is the luxury tail, not a bug.
