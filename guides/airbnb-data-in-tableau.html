Airbnb data in Tableau: load a listings CSV into Tableau Public

Published 2026-09-10. Source: Inside Airbnb, CC BY 4.0. Data Vault is not affiliated with Airbnb or Inside Airbnb.

Honesty note: the pandas prep below was executed against the shipped sample file with pandas 3.0.5, and its output is copied verbatim. The Tableau steps describe Tableau Public menus as documented by Tableau; no Tableau install ran on this build box, so there are no screenshots.

Tableau Public is the free tier of Tableau, and it opens CSV files through the same Text file connector as the paid desktop. What it does not do is fix your types for you. An Airbnb listings CSV carries two fields that break under automatic type inference: a listing ID up to 19 digits long and a neighbourhood column that holds ZIP codes. Prep those in pandas first and the CSV import is boring, which is the goal.

The schema is 12 columns shared by all six cities in the pack: id, name, neighbourhood, latitude, longitude, room_type, price, minimum_nights, availability_365, number_of_reviews, reviews_per_month, last_review. The Airbnb data guide explains each one.

Prep the CSV before Tableau touches it

Tableau reads numeric fields as 64-bit floats, which hold exact integers only up to 2 to the 53rd power. Airbnb IDs pass that mark by seven digits. The other trap is the ZIP column: read as an integer, it sorts by value, joins against other ZIP fields as a number, and drops any leading zero the day your market has one (Boston ZIPs start 021; none of these six cities do, and the sample still should not depend on that luck).

This is the whole prep, executed against the shipped sample. It was run with pandas 3.0.5 and the output below is verbatim:

import pandas as pd

df = pd.read_csv("sample.csv")

# 19-digit listing IDs: float64 rounds anything past 2**53
df["id"] = df["id"].astype("string")
# ZIP codes are labels, not numbers; text keeps any leading zero intact
df["neighbourhood"] = df["neighbourhood"].astype("string")
df["room_type"] = df["room_type"].astype("string")
df["reviews_per_month"] = df["reviews_per_month"].fillna(0).astype("float64")
df["last_review"] = pd.to_datetime(df["last_review"], errors="coerce")

df.to_csv("sample-tableau.csv", index=False)
print(df.shape)
print(df.dtypes.to_string())

What each line buys you in Tableau: the id and neighbourhood casts make both fields text, so the CSV import keeps every digit and joins on exact strings. room_type as text gives clean filter values. Filling reviews_per_month with 0 handles the 4 rows in 20 that have no reviews (Tableau would otherwise plot them as null). The date parse turns last_review from loose text into a real date field Tableau can put on a time axis. Two date-null rows stay null on purpose: a listing with no reviews has no review date, and 0 would be a lie.

Run the same script against any full-pack city CSV before importing; nothing in it is sample-specific.

The CSV import, step by step

  1. Open Tableau Public and pick Text file under Connect. Select the cleaned CSV from the prep step.
  2. On the data source screen, check each column's type icon. id and neighbourhood should read Abc (string); if either shows a number or globe icon, fix it before building anything.
  3. Let the data interpreter run when Tableau offers it; it handles the sub-header quirks some exports carry. On this clean 12-column file it will find nothing to fix, which is the expected result.
  4. Click Sheet 1. Drag latitude to Rows and longitude to Columns; Tableau builds a map axis pair automatically.
  5. Sanity-check the row count in the bottom-left status bar: 20 for the sample, 11,295 for Austin, 90,169 for the whole pack across city files.

If a step misbehaves, the cause is almost always the source file, and rereading the prep script beats debugging inside Tableau.

Live connection or extract?

A live connection re-reads the CSV on every interaction. On the 20-row sample that is instant, and it means every save to the file shows up in the workbook. On the full pack's 90,169 rows it stays workable, since a 12-column CSV of that size is small by Tableau standards, but every filter and zoom pays a disk read.

An extract is Tableau's compressed copy of the data in its own .hyper format. It renders faster and travels with the workbook when you save to Tableau Public, which matters because Tableau Public profiles need the data embedded. An extract freezes the data at creation time.

For this dataset the trade is cheap. The source is a snapshot anyway, frozen at its scrape date, so an extract freezes it a second time and loses nothing. Take the extract for anything you plan to publish, keep the live connection for a quick look at a single city file.

Three viz ideas that work on this schema

1. Price map

Longitude to Columns, latitude to Rows, average of price on Color, room_type on Filters. The sample gives 20 Austin points; the full pack gives all six cities in one view. One caution the price data page documents with real numbers: means ride the luxury tail. San Diego's mean is 483.80 dollars against a median of 322.92, and the same skew shows inside any city map as a few dark dots. Filter out the top of price, or bin it, and neighborhoods become comparable again.

2. Availability histogram

availability_365 to Columns with 30-day bins, COUNT of rows to Rows. In the 20-row sample the median is 285 open nights and half the listings show 300 or more, which is what open calendars with light bookings look like; the tail under 30 nights is where bookings and host blocks pile up. Compute the same histogram per city and the shape differences between markets read straight off the bars.

3. Supply by city bar

Use cities-index.csv, the 6-row per-city summary that ships with the sample: city on Rows, row count on Columns, median_price_usd on Color. New York City tops supply at 30,234 listings with the lowest median at 175 dollars, and the room mix explains it (42 percent private rooms, the highest of the six). Denver anchors the other end at 4,939 listings. The by-city page carries the full table behind this chart.

Gotchas

  • Snapshot bias. Every file is one scrape on one date: Austin 2026-06-22 through New York City 2026-08-10, a 49-day spread across peak season. A Tableau workbook built on these numbers describes those days, and no chart type fixes that. The methodology page covers what a one-day capture can and cannot support.
  • ID precision. Numeric IDs past 2 to the 53rd lose digits silently. If a join or dedupe misfires, check whether both sides treat id as text.
  • Nulls in review fields. Listings with zero reviews have empty reviews_per_month and last_review; 4 of the 20 sample rows. Fill the rate with 0, leave the date null.
  • No occupancy column. A listings snapshot has no booked-nights field. The occupancy page covers the proxies that work instead.

FAQ

How do I import an Airbnb CSV into Tableau Public?

Open Tableau Public, choose Connect to Text file, and pick the CSV. Tableau infers every field type on its own, and that is where the trouble starts: 19-digit listing IDs arrive as numbers past float64 precision, ZIP codes arrive as integers, and dates arrive as text. Run the pandas prep first, save a cleaned copy, and point Tableau at that file. The free 20-row sample works end to end if you want a dry run.

Why do Airbnb listing IDs look wrong in Tableau?

Airbnb listing IDs run up to 19 digits, and numeric fields in Tableau hold exact integers only up to 2 to the 53rd power, about 9 quadrillion. A 19-digit ID like 1690760048869752293 loses its last digits the moment Tableau parses it as a number, and joins or dedupes on that field misfire quietly. Cast the column to text in pandas before the CSV import and Tableau keeps it verbatim.

Is Airbnb data in Tableau live?

No. The CSV is a snapshot: one scrape per city on one date between 2026-06-22 and 2026-08-10. Whatever you build in Tableau describes the market as it stood that day. Hosts reprice constantly and listings churn, so refresh by re-exporting a newer snapshot rather than expecting the workbook to update. The methodology page covers what a one-day capture can and cannot tell you.
