Census data API tutorial: discovery, keys, and ACS rent in Python

Published 2026-09-10. Every command below ran from our box the same day, and every output block is pasted verbatim from that run. The keyed call in the signup section is the one exception: no Census key was registered on our box, so that block documents the request shape from the Census user guide rather than a pasted response.

Three doors into the Census API, and which ones open without a key

The Census Bureau serves all of its machine data from one host, api.census.gov, but the endpoints behave very differently. One GET returns the entire dataset catalog to anyone. Another resolves table codes into variable IDs for anyone. The third, the one that returns actual numbers, redirects keyless callers to a Missing Key page. The doors:

DoorURLKeyBest for
Discovery catalogGET https://api.census.gov/data.jsonnoneFinding which dataset and vintage carries your subject
Dataset metadataapi.census.gov/data/2023/acs/acs1/variables.jsonnoneResolving table codes like B25064 into variable IDs
Data queryapi.census.gov/data/2023/acs/acs1?get=NAME,B25064_001E&for=state:48free, requiredPulling values for states, counties, places, ZIPs

The keyless first two doors are where discovery work happens, and they answer fast. The keyed door is where every number comes from. This tutorial walks each door in order, ending with a pandas pull of ACS median gross rent that runs today with no key at all.

Door one: the discovery catalog holds 1,803 datasets

One request returns the full catalog. It is a 5.2 MB JSON document, so pull it to a file first:

curl -s -w "HTTP %{http_code}, %{size_download} bytes\n" -o /tmp/data.json https://api.census.gov/data.json
HTTP 200, 5212460 bytes

Each entry in the dataset array describes one dataset: a c_dataset path such as ["acs", "acs1"], a c_vintage year, and links to that dataset's variables.json and geography.json. Filter the catalog in Python (Python 3.12, pandas 3.0.5, all in the block below):

import json, urllib.request

HEADERS = {"User-Agent": "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36"}

def get(url):
    req = urllib.request.Request(url, headers=HEADERS)
    with urllib.request.urlopen(req) as r:
        return json.load(r)

catalog = get("https://api.census.gov/data.json")["dataset"]
print("datasets in catalog:", len(catalog))

acs1 = [d for d in catalog if d.get("c_dataset") == ["acs", "acs1"]]
vintages = sorted(d["c_vintage"] for d in acs1)
print("acs1 datasets:", len(acs1), "vintages:", vintages[0], "-", vintages[-1])

vars2023 = get("https://api.census.gov/data/2023/acs/acs1/variables.json")["variables"]
print("variables in 2023 acs1:", len(vars2023))
print("B25064_001E:", vars2023["B25064_001E"]["label"])
print("B25031_004E:", vars2023["B25031_004E"]["label"])

1,803 datasets, of which 270 are ACS products once you count the PUMS, data-profile, and subject-table variants. The 19 core acs1 entries cover every vintage from 2005 through 2024, one per year. The same catalog powers the dataset picker on data.census.gov, so scripting against data.json beats clicking through the web app whenever you need to check several vintages at once.

Door two: endpoint structure is year, dataset, variables

Every data query follows one shape:

https://api.census.gov/data/{year}/{survey}?get={variables}&for={geography}

Concretely, the 2023 American Community Survey one-year release, table B25064 (median gross rent), for Texas:

https://api.census.gov/data/2023/acs/acs1?get=NAME,B25064_001E,B25031_004E&for=state:48

get takes a comma-separated variable list, NAME being the free geography-name variable every dataset carries. for takes a geography level and a FIPS code, and state:* returns every state in one call. The response is a JSON array whose first row holds the variable names and each following row holds one geography's values, so it loads into pandas with one call. That URL shape is what a key unlocks; without one, here is what the same request returns (from our 2026-09-10 run):

curl -s -w "\nHTTP %{http_code} redirect %{redirect_url}\n" "https://api.census.gov/data/2023/acs/acs1?get=NAME,B25064_001E&for=state:48"
HTTP 302 redirect https://api.census.gov/data/missing_key.html

The 2020 decennial PL dataset behaves the same way. The current user guide, on its Query Limits page (revised May 14, 2026), states it plainly: "An API key must be used with all data queries made to the Census Data API," and it caps any single query at 50 variables. Older write-ups across the web describe a 500-queries-per-IP-per-day allowance for keyless calls; that policy no longer matches either the guide or the endpoint, so plan on a key for any data pull.

Variable lookup: variables.json resolves table codes

Table codes like B25064 are census table IDs, not API variable names. The API wants B25064_001E, the estimate variable, and the per-dataset variables.json is the map between the two. The 2023 acs1 file holds 36,724 variables, and each entry carries a label and a predicate type. The rent tables resolve like this:

VariableLabel

B25031_001EMedian gross rent by bedrooms, total

Labels came straight out of the variables.json run in the discovery section, not from memory. B25064 is the all-sizes median gross rent; B25031 splits the same measure by bedroom count, and the _004E slot is the 2BR number, the one that lines up with HUD's 2BR fair market rent. Gross rent means contract rent plus a utilities allowance on both tables, the same rent-plus-utilities basis the FMR uses.

Getting the free key, documented from the user guide

The Census API key guide lists four steps:

  • Open the developers site and click the Request a KEY box, which leads to the form at api.census.gov/data/key_signup.html.
  • Fill out the form. The guide says the email address must end in .com, .net, .org, .gov, or .edu.
  • Check the inbox: the message carries the key code in the body plus a link to register the key.
  • Click that link. The key starts working once registered.

Two gotchas sit in those steps. First, the email rule: a disposable inbox domain such as mail.tm ends in .tm, which is outside the five extensions the guide names, so a throwaway address is the wrong tool for this form. Second, the activation link is not optional; a key pasted straight from the email body before registration is the classic reason a fresh key returns errors. With a registered key, the same Texas call from the last section becomes:

curl -s "https://api.census.gov/data/2023/acs/acs1?get=NAME,B25064_001E,B25031_004E&for=state:*&key=$CENSUS_KEY"

Keep the key out of scripts and out of git: read it from an environment variable, as above. We ran the signup form's rules against the guide, not against a submitted form, because no key was registered on our box for this tutorial; the Census user guide is the authority if their pages move.

The pull that runs without a key today: Census Reporter

Until the key exists, ACS tables are still reachable in pandas. Census Reporter mirrors ACS releases and serves them from api.censusreporter.org with no signup. The same two rent tables, five states, one DataFrame (Python 3.12, pandas 3.0.5, run 2026-09-10):

import json, urllib.request
import pandas as pd

HEADERS = {"User-Agent": "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36"}

def acs_state(fips):
    url = (f"https://api.censusreporter.org/1.0/data/show/latest"
           f"?table_ids=B25064,B25031&geo_ids=04000US{fips}")
    req = urllib.request.Request(url, headers=HEADERS)
    with urllib.request.urlopen(req) as r:
        d = json.load(r)
    fips_id = f"04000US{fips}"
    est = d["data"][fips_id]
    return {
        "state": d["geography"][fips_id]["name"],
        "median_gross_rent": est["B25064"]["estimate"]["B25064001"],
        "median_2br_rent": est["B25031"]["estimate"]["B25031004"],
        "release": d["release"]["id"],
    }

states = {"48":"Texas","36":"New York","29":"Missouri","12":"Florida","28":"Mississippi"}
df = pd.DataFrame([acs_state(f) for f in states])
print(df.to_string(index=False))

One gotcha from the same run: Python's default urllib User-Agent gets an HTTP 403 from Census Reporter's Cloudflare layer. Send a browser-shaped User-Agent header, as the blocks above do, and the JSON arrives. Once a Census key is registered, the keyed endpoint covers the same tables plus every other dataset in the catalog, with the 50-variable-per-query ceiling as the only size limit.

FAQ

Is the Census data API free?

Yes. The key costs nothing, the signup form at api.census.gov/data/key_signup.html takes about two minutes, and the data is public domain. The Census user guide caps a single data query at 50 variables. The discovery catalog at api.census.gov/data.json answers without any key at all, which is where you should spend your first ten minutes.

How do I get a free Census data API key?

Open the Request a KEY box on the Census developers site, which leads to the form at api.census.gov/data/key_signup.html, and fill it out. The Census user guide says the email address you enter must end in .com, .net, .org, .gov, or .edu. A message arrives with the key code in the body and a link to register the key; the key starts working once you click it. Then append &key=YOUR_KEY to every data query.

Can I query the Census API without a key?

On the data endpoints, no. A curl test on 2026-09-10 of api.census.gov/data/2023/acs/acs1 without a key returned HTTP 302 with a redirect to missing_key.html, and the current user guide states that an API key must be used with all data queries. Older write-ups describe a 500-queries-per-IP-per-day allowance for keyless calls; that policy no longer matches the Census user guide or the endpoint behavior we observed. The discovery catalog, variables.json, and geography.json still answer without a key, and Census Reporter serves the same ACS tables with no signup.
