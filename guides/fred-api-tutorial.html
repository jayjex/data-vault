FRED API tutorial: pull Fed data with or without a key

Published 2026-09-10. Every command below ran from our box the same day, and every output block is pasted verbatim from that run.

Two ways into FRED, and when to use each

FRED, the St. Louis Fed's economic database, carries over 800,000 series: mortgage rates, the Case-Shiller home price index, unemployment, GDP, the works. Most tutorials jump straight to the REST API and its key signup, which hides the fastest path. FRED has two doors:

DoorURLKeyFormatBest for
Graph CSV exportfred.stlouisfed.org/graph/fredgraph.csv?id=SERIES_IDnoneCSVPulling a known series into a script or spreadsheet
REST API v1api.stlouisfed.org/fred/series/observationsfree, requiredJSON or XMLSearch, metadata, release dates, bulk workflows

If you know the series ID and want the numbers, the graph endpoint is one GET with no registration. The REST API earns its key when you need search, series metadata, or observation counts programmatically. This tutorial covers both, with the numbers each one actually returned.

The fredgraph.csv trick: any series, no key

Swap any series ID into the id parameter and the graph endpoint serves the full history as a two-column CSV. DGS10 is the 10-year Treasury constant maturity rate. Run it with curl:

curl -s "https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10" | tail -3
observation_date,DGS10
2026-09-01,4.79
2026-09-02,4.79
2026-09-03,4.77

That is 16,873 daily observations back to 1962, in one unauthenticated request. Two URL parameters shape the pull: cosd sets the start date and coed the end date. The same call bounded to the last three days:

curl -s "https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10&cosd=2026-09-01&coed=2026-09-03"

The endpoint returns the identical three rows for that window. One caveat: a bogus series ID does not return a clean 404. id=NOPE123 returns an HTML page, so validate series IDs on fred.stlouisfed.org before your script loops over a list of them.

Getting a free key for the REST API

The keyed door takes about two minutes. The steps, from FRED's own API key docs:

  • Create an account at fredaccount.stlouisfed.org.
  • Open the API Keys page at fredaccount.stlouisfed.org/apikeys and request a key.
  • The key is a 32-character lowercase alphanumeric string. FRED asks for one key per application, and each user of your app should register their own.

Without a key, the REST API rejects every call. This is the exact response our test got on 2026-09-10:

curl -s -w "\nHTTP %{http_code}\n" "https://api.stlouisfed.org/fred/series/observations?series_id=DGS10"
<?xml version="1.0" encoding="utf-8" ?>
<error code="400" message="Bad Request.  Variable api_key is not set.  Read https://fred.stlouisfed.org/docs/api/api_key.html for more information." />
HTTP 400

With a key, the same endpoint takes api_key=YOUR_KEY plus file_type=json and returns the observations as JSON. Add observation_start and observation_end for date bounds, the REST equivalent of cosd and coed. The full endpoint reference lives in FRED's API docs.

FRED in Python: read the CSV straight into pandas

pd.read_csv accepts the fredgraph URL directly, so the whole pull is one line. These examples ran on Python 3.14 with pandas 3.0.5:

import pandas as pd

df = pd.read_csv("https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10")
print(df.tail(2).to_string(index=False))

df.to_parquet("/tmp/dgs10.parquet")
print(pd.read_parquet("/tmp/dgs10.parquet").tail(1).to_string(index=False))
observation_date  DGS10
      2026-09-01   4.79
      2026-09-02   4.79
      2026-09-03   4.77
observation_date  DGS10
      2026-09-03   4.77

The parquet round trip is the caching pattern: download once, write the DataFrame to parquet, and point later analysis at the local file. Series histories rarely change retroactively, so a weekly refresh beats re-downloading 16,000 rows every run. If you prefer keeping the raw file, the CSV also loads through pd.read_csv("/tmp/dgs10.csv") after a plain curl.

Worked example: three housing series in one parquet file

Housing analysis needs three numbers: the mortgage rate buyers face, the price level, and the vacancy rate behind the rent. FRED carries all three. MORTGAGE30US is the weekly 30-year fixed rate, CSUSHPINSA the monthly Case-Shiller national home price index, RRVRUSQ156N the quarterly rental vacancy rate. The frequencies differ, so the script stacks each series on its own dates and lets pandas align them:

import pandas as pd

series = {
    "MORTGAGE30US": "30-year fixed mortgage rate",
    "CSUSHPINSA": "Case-Shiller national home price index",
    "RRVRUSQ156N": "rental vacancy rate",
}
frames = {}
for sid in series:
    df = pd.read_csv(f"https://fred.stlouisfed.org/graph/fredgraph.csv?id={sid}")
    df["observation_date"] = pd.to_datetime(df["observation_date"])
    frames[sid] = df.set_index("observation_date")[sid]

combined = pd.DataFrame(frames)
combined.to_parquet("/tmp/housing.parquet")
for sid in series:
    last = combined[sid].dropna().tail(1)
    print(f"{sid}: {last.index[0].date()} = {last.iloc[0]}")
MORTGAGE30US: 2026-09-03 = 6.71
CSUSHPINSA: 2026-06-01 = 336.663
RRVRUSQ156N: 2026-04-01 = 7.3

Read the output the way an investor would: a 30-year fixed at 6.71 percent, the Case-Shiller national index at 336.663 (January 2000 = 100, so national prices have more than tripled since the base), and a 7.3 percent rental vacancy rate for Q2 2026. The combined parquet keeps each series on its own observation dates, so resample or dropna depending on whether your analysis runs weekly, monthly, or quarterly. FAQ

Does the FRED API require a key?

It depends on the endpoint. The graph endpoint at fred.stlouisfed.org/graph/fredgraph.csv?id=SERIES_ID returns any series as a plain CSV with no key and no signup. The REST API at api.stlouisfed.org requires a 32-character key and returns a 400 error without one. For one-off pulls of a known series, the graph endpoint covers most needs.

How do I get a free FRED API key?

Create an account at fredaccount.stlouisfed.org, open the API Keys page at fredaccount.stlouisfed.org/apikeys, and request a key. It is a 32-character lowercase alphanumeric string, issued at no cost. FRED asks for one key per application, and each user of an app should use their own key.

How do I load FRED data into pandas?

pandas.read_csv accepts the fredgraph.csv URL directly: pd.read_csv("https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10") returns a two-column DataFrame, observation_date and the series value. Add cosd and coed URL parameters to bound the date range, and call to_parquet on the result to cache the series locally so repeat analysis does not re-download it.
