Free crypto data APIs: five price sources tested live

Every call on this page ran on 2026-09-07 from our build box, one curl request per endpoint, and the outputs are pasted verbatim from that run. Prices appear only inside the API payloads; this page is about the pipes, not the market, and nothing here is trading or investment advice.

How this free crypto API comparison was built

Five candidates: the two aggregators every list recommends (CoinGecko, CoinPaprika) and the three exchanges whose public endpoints people copy from Stack Overflow (Coinbase, Binance, Kraken). Same method as our public data APIs list: one curl call each, a fixed User-Agent, HTTP status recorded, response body pasted as returned. Anything that failed got a second attempt after diagnosis, because a failure you cannot explain is not a result.

Three of the five failed the first call, and the reason turned out to sit between our box and the internet, not at the API providers. That failure mode is the part most crypto API tutorials skip, so this page documents it with the exact errors before the comparison tables.

The wall three of five hit: DNS hijack, not the API

Our build box sits behind an Indonesian consumer ISP. First round, plain curl, default DNS: CoinGecko and CoinPaprika returned 200 immediately, and Coinbase, Binance, and Kraken all aborted with the same TLS error:

curl: (60) SSL: no alternative certificate subject name matches target hostname 'api.coinbase.com'

That error means the certificate the server presented does not match the hostname. openssl s_client showed why. The certificate served for api.coinbase.com belongs to internetpositif.id, and the ones for Binance and Kraken belong to internetpositif.id and internetsehatku.com respectively. The ISP's resolver hijacks DNS for these domains and answers with its own block-page servers, whose certificates can never match. The API providers never saw a byte.

HostFirst attemptCertificate actually served
api.coinbase.comcurl error 60, no TLS handshakeCN=internetpositif.id (Let's Encrypt E8)

api.kraken.comcurl error 60, no TLS handshakeCN=internetsehatku.com (Let's Encrypt YE2)

The fix took one minute. Ask a public resolver for the real address, pin it for one request with --resolve, and the same endpoints answered 200 on the same minute:

dig +short @1.1.1.1 api.kraken.com        # 104.17.189.205 on test day

curl -sS --resolve api.kraken.com:443:104.17.189.205 \
  "https://api.kraken.com/0/public/Ticker?pair=XBTUSD"

The resolved address can change, so re-run the dig step rather than copying the IP from here. With the pin, the same endpoints answered 200 on the same minute:

Two honest notes. Pinning an IP from a third-party resolver is a diagnostic tool, not a production pattern; in production, change your resolver to 1.1.1.1 or 8.8.8.8, or run your calls from a network whose DNS you control. And Binance publishes a market-data-only host, data-api.binance.vision, which was not on the ISP's block list at all and answered directly with no DNS work, so the same vendor can be reachable or not depending on which hostname you pick.

General lesson for anyone comparing free crypto APIs from inside a restrictive network: test the resolver before you blame the API. A timeout or a certificate error on one network says nothing about the endpoint on another.

CoinGecko: the one-GET integration

Verbatim body from the test call:

{"bitcoin":{"usd":79076},"ethereum":{"usd":2484.36}}

Headers came back with no rate-limit fields at all, so your code cannot read its own budget here. The response carries cache-control: max-age=30, meaning the number you get can be up to 30 seconds old, and x-data-source: 2.0 identifies the aggregation version. The official errors-and-rate-limits page states the keyless tier is IP-based and shared across everyone on the same IP, and the demo plan with a free key buys a documented 100 calls/min. All requests count toward the limit, including 4xx and 5xx errors, so retry loops burn budget twice.

Coinbase: simplest payload, thinnest docs

Two calls a few minutes apart returned "amount":"79054.635" and then "amount":"79069.945", and the second one, with response headers captured:

{"data":{"amount":"79069.945","base":"BTC","currency":"USD"}}

The Data API reference for prices states the spot, buy, and sell endpoints require no authentication and no scope, and spot accepts a date parameter for historic prices. What Coinbase does not publish, as far as we could find after their docs moved to docs.cdp.coinbase.com, is a keyless rate-limit number; the old API rate-limits page we tried 404s, and the response headers carry no rate-limit fields. Treat the cap as unknown and cache the answer; the payload itself tells you the price is only correct for seconds.

Binance: the only one that tells you the weight you spent

Both official hosts answered. The main API (after the DNS pin) and the market-data-only host that answered with no pinning:

GET https://api.binance.com/api/v3/ticker/price?symbol=BTCUSDT
{"symbol":"BTCUSDT","price":"79081.61000000"}
x-mbx-used-weight-1m: 2

GET https://data-api.binance.vision/api/v3/ticker/price?symbol=BTCUSDT
{"symbol":"BTCUSDT","price":"79029.96000000"}

The x-mbx-used-weight-1m: 2 header matches the documented weight of 2 for one ticker/price call, so a script can watch its own consumption every response. The exchangeInfo endpoint reports the limits themselves, verbatim from test day:

[{"rateLimitType": "REQUEST_WEIGHT", "interval": "MINUTE", "intervalNum": 1, "limit": 6000},
 {"rateLimitType": "ORDERS", "interval": "SECOND", "intervalNum": 10, "limit": 100},
 {"rateLimitType": "ORDERS", "interval": "DAY", "intervalNum": 1, "limit": 200000},
 {"rateLimitType": "RAW_REQUESTS", "interval": "MINUTE", "intervalNum": 5, "limit": 300000}]

The official REST API docs describe the enforcement ladder: exceed the limit and you get HTTP 429 with a Retry-After header; keep going past 429 and the IP gets auto-banned with HTTP 418, with bans scaling from 2 minutes to 3 days for repeat offenders. Limits bind by IP, not by API key. The docs also list alternate base hosts (api1 through api4.binance.com) for when the main host is congested or, in our case, hijacked downstream.

Kraken: one call per second, and the XBT naming trap

Full verbatim body, which is short enough to paste whole:

{"error":[],"result":{"XXBTZUSD":{"a":["79051.00000","1","1.000"],"b":["79050.90000","3","3.000"],
"c":["79051.00000","0.00027526"],"v":["999.39954344","1676.38937064"],"p":["79561.36929","79709.38371"],
"t":[48702,76175],"l":["78960.60000","78960.60000"],"h":["80435.00000","80541.20000"],"o":"80334.40000"}}}

Two things surprise people here. Bitcoin is XBT, not BTC, and the pair gets a doubled prefix, XXBTZUSD, which is also what you pass back in queries. The c array is the last trade price and volume; a and b are the ask and bid with volume and level; v, p, t, l, h, o are today's and 24-hour volume, average price, trade count, low, high, and open. No rate-limit headers come back on this endpoint. The official support article on API rate limits says public endpoints tolerate 1 call per second per IP and stays within the limits at that frequency, with Trades and OHLC additionally limited per currency pair; the private endpoints run a counter system instead (Starter tier: counter max 15, decaying 0.33 per second). Overrun the public limits and Kraken answers with EAPI:Rate limit exceeded or EService: Throttled in the error array.

The headers are what make this one useful for anything beyond a demo:

A limit of 20,000 with a reset counter of 2,105,219 seconds, about 24 days from the test timestamp, lands at the start of the next month: a monthly window, not a daily one. No other source in this comparison returns its own budget, so CoinPaprika is the one where a polling script can self-throttle from the response instead of guessing.

One trap cuts across all five: they answer with different reference prices. Coinbase quotes its BTC-USD market, Binance quotes BTCUSDT against Tether, Kraken quotes XXBTZUSD, and the two aggregators blend venues. The spread between payloads in the same minute on test day was roughly 70 dollars across sources, which is normal market microstructure across markets with different quote assets, not an error to debug.

Which free crypto API fits which job

  • One price check in a script or a bot reply: CoinGecko's simple/price or Coinbase's spot endpoint. One GET, one line of JSON.
  • Continuous polling: CoinPaprika, because the response headers carry the remaining budget, or Binance, because every response reports the weight consumed against the 6,000-per-minute budget.
  • Order-book depth, bids and asks, last trades: the exchange APIs. Kraken's Ticker returns book top and 24h stats in one call; Binance's depth endpoint goes to 5,000 levels with weight scaling by limit.
  • Historic spot by calendar date: Coinbase spot with the date parameter.
  • On-chain state (epochs, validators, supply) instead of market prices: that lives on the chain's own JSON-RPC, which we test in the Solana ecosystem data guide.

FAQ

What is the best free crypto price API?

All five sources on this page returned HTTP 200 with no key on the test day: CoinGecko simple/price, Coinbase /v2/prices spot, Binance ticker/price, Kraken public Ticker, and CoinPaprika tickers. For a one-line price check, CoinGecko has the smallest integration and Coinbase returns the simplest payload. For polling at any volume, CoinPaprika is the only one that exposes its own rate-limit headers, and Binance publishes a per-minute weight budget your code can read from the response headers. For order-book depth and last-trade detail, the exchange APIs (Binance, Kraken) return fields the aggregators do not.

Is the Coinbase API free to use without a key?

The /v2/prices endpoints (spot, buy, sell) need no authentication and no scope per the official Coinbase Developer docs, and our keyless spot call returned HTTP 200. Coinbase publishes no keyless rate-limit number we could find; the old API rate-limits page moved during their docs migration and the spot-price page states only that the endpoint requires no auth. Also note the endpoint answers with a USD amount that changes every call, and the historic spot price accepts a date parameter.

Why did Coinbase, Binance, and Kraken fail on your first try?

The first attempts never reached them. The local ISP resolver hijacked DNS for api.coinbase.com, api.binance.com, and api.kraken.com, answering with IPs that serve unrelated certificates, so curl aborted with error 60 (certificate subject name mismatch). Querying a public resolver (1.1.1.1) for the real IPs and passing them to curl with --resolve made all three return 200 on the same minute. On networks with a clean resolver none of this is needed, and Binance also runs a market-data-only host, data-api.binance.vision, that answered directly without any DNS work.
