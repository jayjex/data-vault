Query HUD fair market rent by ZIP with SQL: DuckDB and SQLite on the FY2027 CSV

FY2027 edition, published 2026-09-10. Data source: HUD FY2027 Fair Market Rent release, effective October 1, 2026. US government data, public domain. Data Vault is not affiliated with HUD. This page documents the data; it is not housing or legal advice.

The short answer

The FY2027 ZIP-level fair market rent file holds 51,871 rows, one per ZIP code, with FMRs for studios through 4-bedrooms in ten columns. Every number on this page came out of that file in DuckDB and SQLite: Texas carries the most ZIP rows at 3,244, the national 2BR median is 1,190 dollars with quartiles at 1,020 and 1,590, and California owns the highest state-level 2BR median at 2,600 dollars.

The queries below are the whole toolkit. Two window functions give you exact percentiles, one JOIN attaches the metro-area medians from the FY2027 metro dataset to the ZIP rows, and one GROUP BY ranks states. Nothing needs pandas, and every result in the text is copy-paste reproducible from the CSV.

What one row looks like

76437,METRO10180M10180,metro,"Abilene, TX MSA",TX,910,920,1150,1490,1790

Ten columns, all typed. The metro flag splits the file into 27,288 metro rows and 24,583 nonmetro rows, and the 51,871 rows cover 2,600 distinct FMR areas: 649 metro areas plus 1,951 nonmetro county groups across 52 state codes (the 50 states, DC and Puerto Rico). Only 395 distinct 2BR values exist across the whole file, so exact-value joins and GROUP BYs see plenty of ties.

Two properties matter before you write a query. First, keep the zip column as text, because ZIPs like 00669 in Aguadilla, PR lose their leading zero in any numeric type. Second, FMRs land on rounded dollar values, so medians computed over an even row count average two integers and can come out at .5; the queries below show the exact-tie behavior.

SQL: exact percentiles with window functions

DuckDB reads the CSV directly, no import step. This is the query behind the distribution table:

-- DuckDB: exact 2BR percentiles in one pass
WITH ranked AS (
  SELECT fmr_2br,
         row_number() OVER (ORDER BY fmr_2br)      AS rn,
         count(*)    OVER ()                       AS n
  FROM read_csv_auto('fmr-by-zip-2027.csv')
)
SELECT
  min(fmr_2br) AS min_2br,
  avg(fmr_2br) FILTER (WHERE rn IN ((n+1)/4, (n+2)/4)) AS p25,
  avg(fmr_2br) FILTER (WHERE rn IN ((n+1)/2, (n+2)/2)) AS med,
  avg(fmr_2br) FILTER (WHERE rn IN ((3*n+1)/4, (3*n+2)/4)) AS p75,
  max(fmr_2br) AS max_2br
FROM ranked;
-- 520, 1020, 1190, 1590, 5260

SQLite needs the rows in a table first and no FILTER clause, so the CASE form does the same job:

-- SQLite: import once, then the same window trick
CREATE TABLE zips (zip TEXT, hud_area_code TEXT, metro TEXT,
  area_name TEXT, state TEXT, fmr_0br INT, fmr_1br INT,
  fmr_2br INT, fmr_3br INT, fmr_4br INT);
.mode csv
.import --skip 1 fmr-by-zip-2027.csv zips

WITH ranked AS (
  SELECT fmr_2br,
         row_number() OVER (ORDER BY fmr_2br) AS rn,
         count(*)    OVER ()                  AS n
  FROM zips
)
SELECT avg(CASE WHEN rn IN ((n+1)/4, (n+2)/4) THEN fmr_2br END) AS p25,
       avg(CASE WHEN rn IN ((n+1)/2, (n+2)/2) THEN fmr_2br END) AS med,
       avg(CASE WHEN rn IN ((3*n+1)/4, (3*n+2)/4) THEN fmr_2br END) AS p75
FROM ranked;
-- 1020, 1190, 1590

Why the avg of two row positions instead of a plain offset pick: with 51,871 rows the median position is a single row, (n+1)/2 = (n+2)/2 = 25,936, so both expressions resolve to the same row and the median is exactly 1,190. Quartile positions land between rows, and the average of the two neighbors is what a percentile function would interpolate. The rn IN (...) form handles both cases in one expression, which is why the same query runs in SQLite and DuckDB unchanged. Both engines verified on the real file; outputs match Python's statistics module to the dollar.

SQL: JOIN the ZIP rows to the metro medians

The metro dataset ships 50 metro areas with a per-metro 2BR median computed across each area's ZIP rows. The join key is hud_area_code on the ZIP side, metro_code on the metro side:

SELECT count(*)                    AS matched,
       sum(z.fmr_2br < m.fmr_2br_median) AS below,
       sum(z.fmr_2br = m.fmr_2br_median) AS at_median,
       sum(z.fmr_2br > m.fmr_2br_median) AS above
FROM zips z
JOIN metros m ON z.hud_area_code = m.metro_code;
-- 10143, 4405, 1150, 4588

The coverage table holds 10,143 of the 51,871 ZIP rows, the ZIPs inside the 50 largest metros by row count. Against their metro medians, 4,405 rows price below, 1,150 land exactly on it and 4,588 price above. Per-area breakdown for the three biggest:

Washington DC's 488 rows carry 162 distinct 2BR values, the most of any area. Los Angeles runs 159 and splits almost evenly, 179 rows above the metro median against 118 below. Philadelphia behaves differently: 236 rows below the median and only 8 above, because the metro's median rides on the expensive Pennsylvania and New Jersey side while most of its ZIP rows are cheaper. These per-metro medians are computed the same way the metro dataset documents: median across the area's ZIP rows, every ZIP weighted once. HUD publishes a second, separate set of ZIP-level figures for some metros (Small Area FMRs), so one area can carry both a single metro median and a ZIP-by-ZIP schedule; the county dataset page covers the median-plus-max rollup at county level for FY2026.

FMR by ZIP in SQL: questions

Which state has the most ZIP codes in the FY2027 fair market rent file?
Texas leads with 3,244 ZIP rows in the FY2027 file, ahead of California at 2,605, Pennsylvania at 2,576 and New York at 2,397. The full top ten adds Illinois (1,939), Missouri (1,908), Ohio (1,884), Iowa (1,718), Michigan (1,556) and Florida (1,552), and those ten states together carry 21,379 of the 51,871 rows.
What is the median 2BR fair market rent for FY2027?
The national 2BR median across all 51,871 ZIP rows is 1,190 dollars, with quartiles at 1,020 (25th) and 1,590 (75th). The cheapest row in the file is ZIP 00669 in Aguadilla, PR at 520 dollars and the most expensive is ZIP 95060 in Santa Cruz-Watsonville, CA at 5,260 dollars. The median moved up from 1,150 in the FY2026 file, a 3.5 percent change of medians (the FY2027 guide reports 3.3 percent, which is the median of ZIP-level percent changes, a different measure).
How do I compute a median in SQL?
Rank the rows with ROW_NUMBER() OVER (ORDER BY fmr_2br), carry the total row count with COUNT(*) OVER (), then average the middle row for odd counts or the two middle rows for even counts, using rn IN ((n+1)/2, (n+2)/2). The pattern runs in SQLite and DuckDB with window functions, and it handles exact ties correctly because each of the 395 distinct 2BR values can occupy many row positions.
