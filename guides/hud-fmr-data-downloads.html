Downloading FMR data from huduser.gov

HUD's FMR datasets page is the primary source and everything on this page traces back to it. For FY2026 there are two workbooks. FY26_FMRs.xlsx holds 4,764 rows at the county level across 14 columns: state codes, hud_area_code, county names, a 10-digit fips, pop2023, and fmr_0 through fmr_4. A second sheet, Field_Descriptions, defines those 14 columns. The ZIP-level detail lives in fy2026_safmrs.xlsx, a 4.2 MB workbook with a single SAFMRs sheet, one row per ZIP area.

The workbooks are fine in Excel and painful everywhere else. They are real .xlsx files, so any script needs pandas plus openpyxl or an equivalent just to read them. The county file and the ZIP file ship separately, so ZIP-level work means a second download. The column names differ from the tidy convention (fmr_0 not fmr_0br, stusps plus state as two columns, a numeric metro flag), so imports want a rename pass. And ZIP and FIPS columns read as numbers unless you format them as text, which strips leading zeros from the New England and Puerto Rico ranges. HUD publishes the data; the shape is up to you.

For context on what the numbers mean, HUD rent data, explained walks the FMR definition, the three CSVs in this pack, and a live MCP query. The full column set is documented in the HUD FMR data dictionary.

Census Reporter: census rent data, not FMR data

Census Reporter deserves a mention because it ranks well for rent data searches and trips people up. It serves American Community Survey tables with no API key and no signup: pick a table, pick geographies, export in the browser. Table B25031 is median gross rent by bedroom count, and B25064 is the overall median, which overlaps with the FMR's rent-plus-utilities basis.

These are census medians, not Fair Market Rents. The FMR sits at the 40th percentile and is tuned toward recent-mover rents; the ACS median is the 50th percentile across all renter-occupied units. Housing agencies set voucher payment standards from the FMR, never from the ACS median. When you need the official program number, huduser.gov is the source. When you want actual observed rents next to the FMR, Census Reporter is the fastest no-key route, and HUD FMR vs census rent works through the full comparison, gap and all.

This site does the xlsx-to-CSV conversion once and ships the result. sample.csv carries 22 real Abilene, TX ZIP rows, free to download with no signup, and sample.json wraps the same rows with the schema. Ten columns, one row per ZIP: zip, hud_area_code, metro, area_name, state, and fmr_0br through fmr_4br. For scripts and agents, downloading anything at all is optional. The dataset-mcp server queries the full 51,895-row file in memory, free, with no API key:

query_dataset(
  "hud-fmr-2026",
  {
    "where": [{ "column": "state", "op": "=", "value": "TX" }],
    "columns": ["zip", "area_name", "fmr_2br"],
    "limit": 5
  }
)

That call matches 3,247 Texas rows and returns up to 100 per call with a next_offset for paging. Setup is one npx command, and the MCP server for Claude Desktop guide walks the config with verified session output.

FAQ: downloading HUD FMR data

Where can I download HUD FMR data for free?
Three places, all free. HUD publishes the FY2026 workbooks on huduser.gov: FY26_FMRs.xlsx at the county level (4,764 rows, 368 KB) and fy2026_safmrs.xlsx at the ZIP level (one SAFMRs sheet, about 51,900 rows, 4.2 MB). Census Reporter serves ACS rent tables such as B25031 with no API key, but those are census medians, not FMRs. Data Vault serves the FY2026 ZIP data as a clean CSV: a free 22-row sample download, free full-file queries over MCP, and the complete 51,895-row pack on Getly.
Is there an official CSV version of the HUD FMR dataset?
No. HUD ships FY2026 FMRs as Excel workbooks only, and the ZIP-level numbers live in a separate SAFMR workbook from the county-level file. Anyone who wants CSV has to read the xlsx with a library like pandas plus openpyxl, skip the extra sheet, rename the 14 source columns, and watch the fips and ZIP columns for lost leading zeros. fmr-by-zip-2026.csv on this site is that conversion, done once and checksummed: ten columns, 51,895 rows, integers rounded exactly as HUD published them.
Should I work with FMR data in Excel, CSV, or an MCP query?
Excel fits a one-off look: open the workbook, filter a state, pivot. CSV fits anything you import more than once: pandas, a database load, a chart script, a demo app. An MCP query fits agents and pipelines that need specific rows on demand, because dataset-mcp filters the full 51,895-row file in memory and returns up to 100 rows per call with no file management. Most developers end up with the CSV as the source of truth and the MCP server for ad hoc pulls.
