HUD SAFMR list: the ZIP-level lookup that beats the metro average

FY2026 edition, published 2026-09-10. Data source: HUD, public domain. Data Vault is not affiliated with HUD. This page documents the data; it is not housing or legal advice.

The short answer

A HUD SAFMR lookup starts with one comparison: the ZIP's own fair market rent against the metro-wide number the ZIP would otherwise carry. HUD's Small Area FMRs exist because that metro-wide number is wrong for both ends of a spread-out market. This page runs the comparison on the real FY2026 file, shows the five widest ZIP-vs-metro gaps with the query output verbatim, and lists the ten metros with the most ZIP-level variation. The concept and the designation mechanics sit in HUD small area FMR, explained; this page is the lookup itself.

Why the metro average is not real in some ZIPs

A metro FMR averages every neighborhood in the market. In a ZIP where rents run far from that average, the metro number describes a place the renter does not live. Two FY2026 rows show both directions of the miss:

In San Diego, the metro base 2BR value is 3,000. ZIP 92004 (Borrego Springs) carries 1,460. The metro number overstates that ZIP by 1,540 a month, more than double what the data says the market asks there.

In the Northwest Hills Planning Region, Connecticut, the most common 2BR value across its 42 ZIP rows is 1,490. ZIP 06752 carries 3,770. A family priced from the base value would face a number 2,280 below the ZIP's own figure.

Same file, same columns, opposite failures. Voucher math built on the metro-wide value either locks a family out of a ZIP that costs more, or sets a standard so far above local rents that landlords in cheaper ZIPs face the wrong benchmark. The small-area version of this story, with the Abilene, TX example worked ZIP by ZIP, is in HUD small area FMR.

The five widest ZIP-vs-metro gaps in the FY2026 file

The HUD FMR FY2026 pack ships all 51,895 ZIP rows in fmr-by-zip-2026.csv. Each row carries a hud_area_code, and within one area code most rows repeat a common value; that most-repeated value is the metro base the ZIP-level numbers diverge from. The comparison query, run on the real file with pandas 3.0.5:

import pandas as pd
df = pd.read_csv("fmr-by-zip-2026.csv", dtype={"zip": str})
base = df.groupby("hud_area_code")["fmr_2br"].agg(
    lambda s: s.mode().iloc[0]).rename("base_2br")
d = df.join(base, on="hud_area_code")
d["gap"] = d["fmr_2br"] - d["base_2br"]
print(d.sort_values("gap", ascending=False).head(5))

The Boston gap is a tie: 02109 and 02110 sit in the table, and 02114, 02199, and 01731 share the same 4,410 against the same 2,560 base. All five rows are ZIPs where the metro-wide value sits far below what the ZIP's own rents support, which is the direction that locks voucher families out of a neighborhood.

The reverse direction misses too. The deepest negative gap in the file is ZIP 92004 in San Diego again: 1,460 against a 3,000 base, −1,540, half the base value. In the other direction, both numbers are wrong for somebody.

One honesty note on the method. The base here is each area's most-repeated 2BR value, the number ZIPs without their own individualized figure carry. In metros where HUD has set ZIP-level values for nearly every ZIP, like San Francisco where only 16 of 113 rows carry the base, the mode is the most common ZIP value rather than a metro-wide average. The comparison still ranks the divergence; treat the base as an operational benchmark, not an official HUD publication. Single-ZIP examples from the same file, including the Abilene row for ZIP 79508, are in HUD FMR by ZIP code.

How to read the values

Each ZIP row carries ten columns: zip, hud_area_code, metro, area_name, state, and fmr_0br through fmr_4br. The five fmr values are monthly dollars, rounded as HUD published them, for standard-quality units with utilities included. fmr_2br is the number most voucher conversations turn on; the 0BR through 1BR and 3BR through 4BR values scale the same comparison to other household sizes.

Reading a lookup in three steps:

  • Find the ZIP row by filtering on the zip column. That row's fmr values are the ZIP-level figures, and where a designated SAFMR applies, they are the benchmark.
  • Find the base: within the same hud_area_code, the value most rows repeat. The gap between the ZIP row and the base is the ZIP-vs-metro spread this page ranked.
  • Check the sign. A ZIP above its base means the metro number understates local rents; a ZIP below means it overstates them. Both matter, in different directions, for payment standards and for any rent benchmark keyed to HUD numbers.

Column types and first-row examples for every field sit in the HUD FMR data dictionary, and the designation rules deciding when the ZIP value governs are in HUD small area FMR, explained.

SAFMR list questions

Where can I find the list of HUD SAFMR ZIP codes?
HUD publishes the designated metro areas with each fiscal year's FMR release, and the ZIP-level SAFMR tables on huduser.gov. The FY2026 ZIP file in the Data Vault pack covers all 51,895 ZIP rows with the columns you need to filter them: zip, hud_area_code, metro, area_name, state, and fmr_0br through fmr_4br. It carries no SAFMR flag column, so ZIP-level variation against the metro base is the signal to confirm against HUD's tables.
How do I find the ZIPs whose FMR is furthest from their metro average?
Group the ZIP file by hud_area_code, take each group's most common fmr_2br value as the metro base, and subtract it from every ZIP row in the group. Run on the FY2026 file, the widest 2BR gap is ZIP 06752 in the Northwest Hills Planning Region, CT: 3,770 against a 1,490 base, +2,280, which is 153 percent above the base. Next come 94404 in San Francisco at +2,020 and 94505 in Stockton-Lodi at +1,920.
Does every ZIP code have a SAFMR?
The FY2026 ZIP file carries a value for every one of its 51,895 ZIP rows, and ZIP values vary inside nearly every metro: 36,429 rows differ from their area's most-repeated 2BR value. Carrying a ZIP value and being a designated SAFMR are different things. HUD's annual notice decides where agencies must use ZIP-level numbers, and in the rest of the country the metro FMR governs. Confirm any ZIP against HUD's SAFMR tables before relying on it.
