JSON API tutorial: read JSON from a public API in Python

Published 2026-09-10. Every request below ran live from our box on 2026-09-07 (Python 3.14, requests 2.32.5, jq 1.8.1), and every output block is pasted verbatim from that run.

The shape you get back

A JSON API answers an HTTP request with a body of JSON text: objects in {}, arrays in [], strings, numbers, booleans, and nulls. Python turns that into dicts, lists, and scalars with one call. Here is the ESPN NFL scoreboard endpoint, a real keyless API we also list in our public data APIs list:

import requests

r = requests.get("https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard")
print(r.status_code, r.headers["content-type"])
data = r.json()
print(type(data).__name__, list(data))
print(len(data["events"]))
200 application/json;charset=UTF-8
dict ['leagues', 'season', 'week', 'events', 'provider']
16

Three things to check before you trust r.json(): the status code, the content type, and the body. .json() raises json.decoder.JSONDecodeError when the body is HTML or empty, which is exactly what some providers return when they throttle you or lose a path. The two checks above cost one line each and turn a confusing traceback into a clear message.

No requests installed? The stdlib covers the same ground:

import json
from urllib.request import urlopen

with urlopen("https://api.open-meteo.com/v1/forecast?latitude=40.71&longitude=-74.01&current=temperature_2m") as resp:
    data = json.load(resp)
print(data["current"])
{'time': '2026-09-07T15:00', 'interval': 900, 'temperature_2m': 22.4}

urlopen raises HTTPError on 4xx and 5xx instead of handing you the response, so the error path differs slightly. We use requests in the rest of this tutorial because its error handling reads better.

Walking the nesting: arrays of objects

Real APIs nest. The ESPN response puts each game in an object inside the events array, and each game's teams in another array under competitions. Index and loop the way you would any Python structure:

game = data["events"][0]
print(game["name"], game["date"])
for c in game["competitions"][0]["competitors"]:
    print(c["homeAway"], c["team"]["displayName"], c["score"])
New England Patriots at Seattle Seahawks 2026-09-10T00:20Z
home Seattle Seahawks 0
away New England Patriots 0

Two habits save hours here. First, print list(data) and list(game) to see the keys a level actually has; guessing key names from memory is how KeyError happens. Second, watch for scalars that arrive as strings: ESPN ships scores as strings ("0"), BLS ships values as strings, and the Open-Meteo response above ships numbers. Cast after you inspect, and check for null (None) while you are at it, because pregame scores and missing observations both arrive as null in many APIs.

Pagination: when one response is not all of it

Big endpoints page their answers. The World Bank indicator API returns a top-level two-element array, which surprises people expecting an object at the root: element 0 holds page metadata, element 1 holds the rows.

import requests

meta, rows = requests.get(
    "https://api.worldbank.org/v2/country/all/indicator/SP.POP.TOTL",
    params={"format": "json", "page": 1, "per_page": 5},
).json()
print(meta["page"], "of", meta["pages"], "|", meta["total"], "rows")
for row in rows:
    print(row["country"]["value"], row["date"], f"{row['value']:,}")
1 of 3498 | 17490 rows
Africa Eastern and Southern 2025 788,844,284
Africa Eastern and Southern 2024 769,280,888
Africa Eastern and Southern 2023 750,491,370
Africa Eastern and Southern 2022 731,821,393
Africa Eastern and Southern 2021 713,090,928

The loop writes itself from the metadata: request page=1, read meta["pages"], then walk page = 2 ... pages, extending a list with each page's rows until you have meta["total"]. Keep per_page honest too; a request for page 4000 of nothing returns an error, not an empty list, on some providers. APIs differ in where the counts live (a meta key, a Link header, a next URL in the body), so read them off the first response before coding the loop.

Two ways an API says no

Errors arrive in two shapes and you need code for both. The first is a real HTTP error status with a JSON body explaining itself. Ask Open-Meteo for a misspelled variable and it answers 400 with a reason:

import requests

r = requests.get(
    "https://api.open-meteo.com/v1/forecast",
    params={"latitude": 40.71, "longitude": -74.01, "current": "temperatures_2m"},
)
print(r.status_code)
print(r.json())
400
{'error': True, 'reason': "Data corrupted at path ''. Cannot initialize SurfacePressureAndHeightVariable<VariableAndPreviousDay, VariableOrSpread<ForecastPressureVariable>, ForecastHeightVariable> from invalid String value temperatures_2m."}
r.raise_for_status()
requests.exceptions.HTTPError: 400 Client Error: Bad Request for url: https://api.open-meteo.com/v1/forecast?latitude=40.71&longitu...

Call r.raise_for_status() right after every GET and wrong URLs, typos, and auth failures crash your script with the URL in the message instead of silently parsing garbage.

The second shape is nastier: HTTP 200 with the error inside the body. On 2026-09-07, after the keyless daily quota ran out, the BLS Public Data API v2 answered a request for unemployment series LNS14000000 like this (status code first, then body):

import requests

r = requests.get("https://api.bls.gov/publicAPI/v2/timeseries/data/LNS14000000")
print(r.status_code, r.json()["status"])
200 REQUEST_NOT_PROCESSED
{"status":"REQUEST_NOT_PROCESSED","responseTime":0,"message":["Request could not be serviced, as the daily threshold for total number of requests allocated to the user with registration key  has been reached."],"Results":{}}

Status code 200, error message in message[], empty Results. raise_for_status() sees nothing wrong. The fix is checking the status field each API documents. For BLS:

body = r.json()
if body.get("status") != "REQUEST_SUCCEEDED":
    raise SystemExit(f"BLS error: {body['message'][0][:80]}")
BLS error: Request could not be serviced, as the daily threshold for total number of reques...

That check is why the same endpoint appears with live data in our API list from 2026-09-09 and as an error here a day later. Quotas expire, bodies lie, and the code that survives checks both layers.

The file that breaks json.loads: concatenated arrays

One trap from our own pipeline. Building the Superteam Earn dataset, the source API dumped each page as a JSON array, and the raw snapshot ended up as several arrays back to back in one file: 51 card objects that were 17 unique listings across 3 pages. Feed that file to json.loads and it stops after the first array:

import json

raw = '[{"id": 1}, {"id": 2}] [{"id": 3}]'
json.loads(raw)
json.decoder.JSONDecodeError: Extra data: line 1 column 24 (char 23)

The error message even names the position where the second document starts. Concatenated arrays look like JSONL (newline-delimited JSON) at a glance, but JSONL is one object per line and parses line by line; concatenated arrays have no separator at all. JSONDecoder.raw_decode handles both, because it parses one document and reports where it stopped:

decoder = json.JSONDecoder()
arrays = []
pos = 0
while pos < len(raw):
    while pos < len(raw) and raw[pos].isspace():
        pos += 1
    obj, pos = decoder.raw_decode(raw, pos)
    arrays.append(obj)
print(len(arrays), [len(a) for a in arrays])
2 [2, 1]

Merge the pages after parsing (rows = [r for a in arrays for r in a]), then dedupe on the record id, because paginated APIs happily hand you the same listing twice across page boundaries. Our 51 cards collapsed to 17 unique listings on that dedupe.

Quick look with curl piped to jq

Before writing Python, eyeball the response. curl fetches, jq formats and queries, and the pipe answers structural questions in seconds:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard" | jq '.events[0].name'
curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard" | jq '.events | length'
"New England Patriots at Seattle Seahawks"
16

jq keys lists the top-level keys, jq '.events[0]' prints the first game in full, and jq '.events | map(.name)' lists all 16 matchups. Once the path is confirmed in jq, the same path works in Python as data["events"][0]["name"]. For one-off pulls this is the whole script; for anything scheduled, move it into requests so you get status checks and retries.

FAQ

How do I read JSON from an API in Python?

Call requests.get(URL) and call .json() on the response: r = requests.get("https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard") followed by data = r.json() returns a Python dict built from the response body. Check r.status_code and r.headers["content-type"] first, because .json() raises a JSONDecodeError when the body is HTML or empty. The stdlib alternative is json.load(urlopen(URL)) from urllib.request, which needs no install.

What if the API returns HTTP 200 but no data?

Some APIs report failures inside a 200 body. The BLS Public Data API v2 answered our request for series LNS14000000 with HTTP 200 and the body {"status":"REQUEST_NOT_PROCESSED","message":["daily threshold ... reached"],"Results":{}} once the keyless daily quota ran out. So after r.json(), check the status field the API documents, not just the HTTP code. A defensive check like raising when body.get("status") != "REQUEST_SUCCEEDED" catches the silent failure.

How do I fetch all pages from a JSON API?

Most paginated JSON APIs put page counts in the response. The World Bank API returns a two-element top-level array: element 0 is metadata with page, pages, per_page, and total, and element 1 is the row array. Loop page = 1 through meta["pages"], request each page, and extend a results list with the rows until you have all meta["total"] of them.
