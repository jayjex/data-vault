Drinking water points in Lagos, Nairobi and Addis Ababa, counted from OpenStreetMap

Published 2026-09-10. Data source: OpenStreetMap Civic Amenities, Lagos-Nairobi-Addis Ababa, 2026-09, nine counts from Overpass API out count queries on 2026-09-10, cross-checked on a second mirror with 8 of 9 numbers matching. Boundary details come from the dataset schema. This page documents the data.

The short answer

Three cities, three amenity types, nine counts, and one amenity carrying nearly everything. OpenStreetMap contributors have mapped 2,240 public features inside the boundaries of Lagos, Nairobi, and Addis Ababa: 2,239 drinking water points, zero public bookcases, and one bike repair stand, a snapshot taken 2026-09-10 with a base timestamp of 2026-09-08T19:24:39Z. Nairobi holds 2,175 of the features, 97.1 percent of the file, and its drinking-water count alone (2,174) covers 97.1 percent of the fountains in all three cities combined.

The five zero cells and the single 1 are as informative as the thousands. This is the only file in the catalog's civic series where an entire amenity column reads zero in every city, and the schema states outright that the zeros are real results. Both tables below recompute from the free nine-row CSV, and the two SQL blocks at the end of this page return them verbatim.

The zero columns and the one repair stand

Zeros in a count table can mean two things: nobody mapped the thing, or nobody mapped the tag. The schema answers for the bookcase column: no public_bookcase is mapped anywhere in the three boundaries. For the repair column, exactly one bicycle_repair_station exists, gitonga bicycle services (node 12243521973, -1.3111768, 36.8686335), a bike shop and the county's only mapped stand. Whether the zeros reflect a tagging gap or an infrastructure gap is a fieldwork question the file cannot answer.

Context from the rest of the series sharpens the picture. Six files in the catalog's civic series count public bookcases, and every one of the other five has at least one nonzero cell: New York City 221 in the US file, Berlin 114 and Paris 165 in the EU file, Tokyo 3 in the Asia file, São Paulo 4 in the Latin America file, Istanbul 1 in the MENA file. Amsterdam reads 0 bookcases in the EU file while Berlin in the same file reads 114, so a zero sits next to a busy column even inside one region. Africa's column stays zero end to end.

The drinking-water cells carry their own texture. Lagos's 60 fountains sit mostly in one branded “Clean Water” cluster around 6.494-6.495 N, 3.388 E, including node 7376214198 and a second tap at 7376214199. Nairobi's 2,174 are mostly unnamed tap points with a dense Kibera cluster around -1.31, 36.79, including the Kibera Water & Sanitation Project (node 612007474); the schema attributes the count to community water-point mapping projects rather than decorative fountains. Addis Ababa holds exactly 5 drinking-water features in the whole city, among them Esa bling (node 6665462785) and Minch water filters (node 10800986807).

Three boundaries, one admin level

Where the Sydney-Melbourne-Auckland file counts three different kinds of area, this file's three boundaries are all the same kind, and the schema says so. Lagos counts run inside R3718182, Lagos State (admin_level 4), whose built-up core matches the city but which also includes Epe, Ikorodu, and Badagry. Nairobi counts run inside R3492709, Nairobi County (admin_level 4), which covers the whole pre-2010 county rather than the old city council boundary. Addis Ababa counts run inside R1707699, the city administration itself, because Addis Ababa is a chartered city, so the administration is the city.

Two boundary picks deserve the detail. Nominatim's top hit for “Lagos” is a city place node (27565124), not an area, so the counts use Lagos State, and the schema flags that the numbers are therefore province-wide rather than downtown-only. All three relations carry Overpass areas directly, with no district-child fallback needed, which the schema contrasts with Mumbai in the MENA batch. Read the counts as OpenStreetMap coverage inside these admin areas: exact for what was mapped on the snapshot date, estimates for what stands on the ground.

Where Nairobi stands across the series

Cross-file, Nairobi's 2,174 drinking-water points rank second among single-city counts in the catalog's civic series. Sydney holds the top count at 2,479 in the Oceania file, and Nairobi leads Tokyo (2,163) and Madrid (2,058). The schema still describes Nairobi's 2,174 as the largest single-city drinking-water count in the catalog's OSM civic series; the Oceania batch added the same day carries the higher Sydney figure, and this page reports both numbers.

The comparison holds within a theme on purpose. This file counts fountains, bookcases, and repair stands; the Oceania and US2 files count fountains, toilets, and benches, so a bench-to-fountain ratio does not transfer across files. What does transfer is the drinking-water column, which every file in the series measures with the same amenity=drinking_water tag.

Methodology: two mirrors, four months apart

The source file is the nine-row africa-civic-amenities.csv (ODbL, © OpenStreetMap contributors). Each cell is an Overpass API out count query for one amenity type inside one city area, counting nodes and ways together; relations are ignored, and none exist for these tags in the three areas. City areas were resolved through Nominatim relations and passed to Overpass as 3600000000-offset area IDs.

The primary run used the maps.mail.ru mirror (keyless, base timestamp 2026-09-08T19:24:39Z) on 2026-09-10. A parallel count run on the kumi.systems mirror (base timestamp 2026-05-06, four months staler) matched 8 of 9 numbers exactly: Lagos 60 / 0 / 0 and Addis Ababa 5 / 0 / 0 identical, Nairobi's repair stand 1. Nairobi's drinking-water count came back 2,173 on the staler base against 2,174 here, one edit in the gap between the two mirrors.

Counts are a snapshot, OSM moves daily, and the three admin_level 4 boundaries reach past the built-up cores, so treat the numbers as province-wide coverage inside the mapped boundaries. The bookcase and repair themes sit on a much smaller mapping base in this region than the bench and toilet themes of the US files, which is why this page compares within a theme across files and keeps ratios out.

Recompute the tables yourself

Load the CSV into SQLite as civic, three columns per row. The first block returns the raw board:

-- SQLite: all nine city-amenity counts, ranked by raw count
CREATE TABLE civic (city TEXT, theme TEXT, count INT);
.import --skip 1 africa-civic-amenities.csv civic

SELECT rn, city, theme, count, share_of_city
FROM (SELECT city, theme, count,
             ROUND(count * 100.0 / SUM(count) OVER (PARTITION BY city), 1) AS share_of_city,
             ROW_NUMBER() OVER (ORDER BY count DESC, city, theme) AS rn
      FROM civic)
ORDER BY rn;
-- Rows: 1 Nairobi water fountains 2174 100.0,
-- 2 Lagos water fountains 60 100.0,
-- 3 Addis Ababa water fountains 5 100.0,
-- 4 Nairobi bike repair stations 1 0.0,
-- 5 Addis Ababa bike repair stations 0 0.0,
-- 6 Addis Ababa public bookcases 0 0.0,
-- 7 Lagos bike repair stations 0 0.0,
-- 8 Lagos public bookcases 0 0.0,
-- 9 Nairobi public bookcases 0 0.0.

The second block returns the file's shape: theme totals, Nairobi's share, the median, the zero-cell count, and the span across nonzero cells, then per-city totals:

-- SQLite: shape of the file
WITH r AS (SELECT count AS v, ROW_NUMBER() OVER (ORDER BY count) AS rn,
                  COUNT(*) OVER () AS n FROM civic),
     t AS (SELECT theme, SUM(count) AS n FROM civic GROUP BY theme),
     c2 AS (SELECT city, SUM(count) AS n FROM civic GROUP BY city)
SELECT
  (SELECT SUM(v) FROM r) AS features,
  (SELECT n FROM t WHERE theme = 'water fountains') AS fountains,
  (SELECT n FROM t WHERE theme = 'public bookcases') AS bookcases,
  (SELECT n FROM t WHERE theme = 'bike repair stations') AS repair_stands,
  (SELECT n FROM c2 WHERE city = 'Nairobi') AS nairobi_total,
  (SELECT ROUND(n * 100.0 / (SELECT SUM(n) FROM c2), 1) FROM c2
   WHERE city = 'Nairobi') AS nairobi_share,
  (SELECT v FROM r WHERE rn = (n+1)/2) AS median_count,
  (SELECT SUM(CASE WHEN v = 0 THEN 1 ELSE 0 END) FROM r) AS zero_cells,
  (SELECT MAX(v) FROM r) AS largest_count,
  (SELECT ROUND(MAX(v) * 1.0 / MIN(v), 1) FROM r WHERE v > 0) AS largest_over_floor;
-- 2240 / 2239 / 0 / 1 / 2175 / 97.1 / 0 / 5 / 2174 / 2174.0.

-- per-city totals and the drinking-water share
SELECT city, SUM(count) AS city_total,
       ROUND((SELECT count FROM civic WHERE city = c.city AND theme = 'water fountains')
             * 100.0 / SUM(count), 1) AS fountain_share
FROM civic c
GROUP BY city
ORDER BY city_total DESC;
-- Rows: Nairobi 2175 100.0,
-- Lagos 60 100.0,
-- Addis Ababa 5 100.0.

Run in one session, both blocks return exactly the rows quoted in the comments. The shares round to 100.0 for every nonzero fountain cell because each city's file is, to one decimal, all fountains.

Lagos, Nairobi and Addis Ababa counts: questions

Which of the three cities has the most drinking water points?
Nairobi on raw counts: 2,174 of the file's 2,239 drinking-water features, 97.1 percent, against Lagos's 60 and Addis Ababa's 5. The schema attributes Nairobi's count to community water-point mapping projects rather than decorative fountains, and most of the 2,174 are unnamed tap points with a dense Kibera cluster. All three boundaries are admin_level 4 areas that reach past the built-up core, so the counts are province-wide rather than downtown-only.
Why are the bookcase and bike repair counts zero?
The zeros are real results, not missing data: the schema states that no public_bookcase is mapped anywhere in the three boundaries, and bicycle_repair_station appears exactly once, at a Nairobi bike shop (node 12243521973). Whether a zero column reflects a tagging gap or an infrastructure gap is a fieldwork question the file cannot answer. Six files in the catalog's civic series count bookcases, and this is the only one where the whole column reads zero; the EU file's Amsterdam also reads 0 while Berlin in the same file reads 114.
How were the counts taken and verified?
Each cell is an Overpass API out count query for one amenity type inside one verified boundary relation, run on 2026-09-10 against the maps.mail.ru mirror with base timestamp 2026-09-08T19:24:39Z. A parallel run on the kumi.systems mirror (base 2026-05-06, four months staler) matched 8 of 9 numbers exactly; Nairobi's drinking-water count was 2,173 on the staler base versus 2,174 here, one edit in the gap between the two mirrors. Nodes and ways are counted; relations are ignored, and none exist for these tags in the three areas.
