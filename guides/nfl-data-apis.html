ESPN site API: the fastest route to a scoreboard

ESPN serves the JSON its own site and apps render, under site.api.espn.com, and the public endpoints answer any client with no key:

import requests

r = requests.get(
    "https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard",
    params={"seasonType": 2, "week": 1, "dates": 2025},
    timeout=30,
)
r.raise_for_status()
print(r.status_code, len(r.content))    # 200 138361
print(len(r.json()["events"]))          # 16
print(r.json()["events"][0]["name"])    # Dallas Cowboys at Philadelphia Eagles

What you get: fixtures and results as nested JSON, one call per week via week and dates, plus a teams endpoint that returned all 32 clubs (200, 148,848 bytes on the checked date). The upside is speed; the price is a contract. The endpoint is undocumented, with no published schema, no versioning promise, and no published rate limit, so keep timeouts on, cache what you already fetched, and back off on errors.

History depth is the other limit. The dates parameter reaches back at least a season or two (2025 week 1 worked on the checked date), but there is no claim anywhere about how far, and nobody builds a multi-decade dataset on a display feed. nflverse releases: full history as static CSV

The nflverse-data project publishes the full game history as a GitHub release asset. Strictly speaking this is a file download with stable URLs rather than an API, and that is exactly why it is dependable: the URL either returns the same file or a clean error. A plain requests call follows the redirect to GitHub's asset CDN:

import requests

url = "https://github.com/nflverse/nflverse-data/releases/download/schedules/games.csv"
r = requests.get(url, timeout=120)
r.raise_for_status()
print(r.status_code, len(r.content))    # 200 2177161
print(r.content.count(b"\n"))           # 7549  (7548 rows + header)

7,548 game rows, 1999 through the scheduled 2026 season. Each release directory carries a freshness stamp:

stamp = requests.get(
    "https://github.com/nflverse/nflverse-data/releases/download/schedules/timestamp.json",
    timeout=30,
).json()
print(stamp)    # {'last_updated': '2026-09-07 09:36:23 EDT'}

Schedules are one release among several. The stamps for the others came back the same way on the checked date: pbp play-by-play updated 2026-08-26, player_stats updated 2025-05-07, rosters updated 2026-09-07. Licensing is the cleanest in the space: CC BY 4.0, commercial use allowed with credit as "Data from nflverse, CC BY 4.0".

nfl_data_py and nflreadpy: the same files with an import

Two packages pull the nflverse releases into a DataFrame without you touching URLs. Their current state, read live from the PyPI JSON API (https://pypi.org/pypi/<name>/json, both 200):

PackageVersionFrameKey schedule callDependencies that matter
nfl_data_py0.3.3pandasimport_schedules()pins numpy<2.0 and pandas<2.0, plus appdirs>1 and fastparquet>0.5
nflreadpy0.1.5polarsload_schedules()requests, polars>=0.20.0, platformdirs, tqdm, pydantic

The catch sits in the first row: nfl_data_py 0.3.3 requires numpy under 2.0 and pandas under 2.0, so installing it into a current environment can downgrade or refuse. nflreadpy is newer, built by the nflverse org itself, and leans on polars with no pandas pin. Underneath, both download the exact files from the nflverse section above, so data quality is identical; the choice is a dependency question, and requests against the URLs directly sidesteps both packages' constraint sets entirely.

The official NFL API: 401 without a deal

The league runs its own host, api.nfl.com, and it is closed to walk-up traffic. Two calls on the checked date, output verbatim in kind:

r = requests.get("https://api.nfl.com/", timeout=30)
print(r.status_code)    # 401

r2 = requests.get("https://api.nfl.com/content/v1/videos/football/nfl/2026", timeout=30)
print(r2.status_code)   # 401

The body is an XML 401 Unauthorized page on both. developer.nfl.com, the portal for the league's API program, also answered 401 to a plain programmatic fetch. So the practical picture: keys are issued through the portal to approved partners, feeds above that carry license terms, and there is no public, keyless tier to test against. When a vendor page says "official NFL data", read that as licensed and priced, and check whether ESPN or nflverse covers your need before getting on that path. The opposite end of that spectrum is a seller charging per request instead of per contract: the x402 data API guide shows how HTTP 402 payments work on a live API that serves these same nflverse game rows.

NFL data API questions

Is there an official NFL data API?
Nothing public. The league's api.nfl.com answered 401 Unauthorized to plain unauthenticated calls on 2026-09-10, and developer.nfl.com returned 401 to a programmatic fetch the same day. Access runs through a developer portal with keys for approved partners and licensed feeds on top. Anyone without a deal with the league sources game data from ESPN's site API or the nflverse releases instead.
What is the difference between nfl_data_py and nflreadpy?
Both wrap the same nflverse releases, so the underlying rows are identical. nfl_data_py 0.3.3 returns pandas DataFrames through import_schedules() and pins numpy<2.0 and pandas<2.0, which can collide with a current environment. nflreadpy 0.1.5 returns polars DataFrames through load_schedules() and depends on requests, polars, platformdirs, tqdm, and pydantic. Both version numbers and pins were read live from the PyPI JSON API on 2026-09-10.
Which NFL data API should I use?
Match the source to the job. A current-week score query: ESPN's site API, keyless and a few KB per call. Full 1999-2026 game history: the nflverse games.csv release file, 7,548 rows in one download under CC BY 4.0. A pipeline that also needs play-by-play or rosters: nfl_data_py or nflreadpy, which pull the same releases with one import. A contract and licensed feed: developer.nfl.com, where the keys live.
