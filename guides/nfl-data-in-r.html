NFL data in R: load the games CSV with readr and dplyr

Guide to the NFL Games & Betting Lines 1999-2026 pack · free 22-row CSV sample · every column explained in the games.csv column guide · prefer Python? The pandas quickstart runs the same sample.

Two lines of R load the NFL sample and print its size:

library(readr)

games <- read_csv("https://jayjex.github.io/data-vault/data/nfl-games/sample.csv")
dim(games)

The file is 46 columns and 22 data rows, one row per game, weeks 1 and 2 of the 1999 season. read_csv accepts the URL directly, so nothing to download first, no signup, no API key, and it returns a tibble that pipes straight into dplyr. The three analyses below use only filter, group_by, summarise, and merge; a data.table version of each runs on the same page.

The machine that builds this site has no R runtime, so the code on this page is untested in R, syntax verified against the readr and dplyr documentation on cran.r-project.org (readr 2.x column guessing, dplyr 1.2.1). Every number shown in the output comments comes from the real CSV file on this site.

Setup

Install the two tidyverse packages once:

install.packages(c("readr", "dplyr"))

Reading a URL instead of a local path means the same two lines work on any machine with network access. If you would rather pin a local copy, download the sample CSV and point read_csv at the filename.

Load the sample and check it

The types worth one glance before the analyses:

library(readr)

url <- "https://jayjex.github.io/data-vault/data/nfl-games/sample.csv"
games <- read_csv(url)

dim(games)                # 22 46
games$game_id[1]          # "1999_01_MIN_ATL"
class(games$home_score)   # "numeric"
sum(is.na(games$temp))    # 6
  • game_id is the join key in season_week_AWAY_HOME format, like 1999_01_MIN_ATL. readr reads it as character without help; the letters and _ characters force that guess.
  • temp and wind hold NA for the 6 dome games, where the stadium roof was closed and the number was never recorded. The full column list lives in the games.csv column guide.
  • The sample carries 10 fully empty columns (gametime, nfl_detail_id, pff, ftn, and the moneyline and odds columns). readr's documented guessing rules turn an all-missing column into logical NA. If that bothers you, pin them: read_csv(url, col_types = list(gametime = col_character(), referee = col_character())) or name any other column the same way.
  • spread_line is stored relative to the home team: -4 means the away team is favored by 4.

Three dplyr analyses

1. Top 5 teams by wins, from the sample

library(dplyr)

games |>
  select(game_id, away_team, away_score, home_team, home_score) |>
  mutate(winner = if_else(home_score > away_score, home_team, away_team)) |>
  count(winner, name = "wins") |>
  arrange(desc(wins), winner) |>
  slice_head(n = 5)
#   winner  wins
#   DET         2
#   JAX         2
#   PIT         2
#   ARI         1
#   BUF         1

Detroit, Jacksonville, and Pittsburgh opened 2-0 in the sample; the remaining games split across 16 teams at 1 win each, so the 4th and 5th rows are alphabetical tie-breaks, not a real ranking. That is what 22 rows are for: learning the shape of the verbs. A count() call is shorthand for group_by(winner) |> summarise(wins = n()), the same aggregation in longer form. To rank whole seasons, run the identical pipeline on the full 7,548-row file, or read the pre-aggregated table in the team-records CSV guide.

2. Dome vs outdoor scoring with group_by and summarise

games |>
  group_by(roof) |>
  summarise(games = n(), avg_total = mean(total))
#   roof     games avg_total
#   dome         6      38.0
#   outdoors    16      45.5

total is combined points. The 6 dome games averaged 38.0, the 16 outdoor games 45.5. The games column keeps the sample-size gap visible: 6 rows is a handful, so treat the gap as a dplyr exercise, not a finding. On the full file the same group_by runs across 27 seasons. The roof split is one slice of the weather story; NFL stadium weather, read from the same columns covers temp, wind, and what the file can and cannot say about kicking.

3. Join the spreads and check the favorites

The closing line already sits in spread_line on every row, so the join example works with a second real file: season-summaries.csv, 27 rows, one per season, free. Merge it on season and the per-season context lands next to each game:

summaries <- read_csv("https://jayjex.github.io/data-vault/data/nfl-games/season-summaries.csv")

games |>
  merge(summaries, by = "season") |>
  select(game_id, home_score, away_score, home_win_pct)
#            game_id home_score away_score home_win_pct
#      1999_01_MIN_ATL         14         17        0.598
#      1999_01_KC_CHI          20         17        0.598
#      ...

The sample's 22 games split 10 home wins and 12 away wins, a .455 home win rate, while the merged column shows the full 1999 season went to the home team 59.8 percent of the time. Two weeks of September is noise; the season table is the baseline. For the spread itself, mark the favorite and check the cover in one mutate:

games |>
  mutate(
    fav_covered = if_else(
      spread_line < 0,
      (home_score - away_score) + spread_line > 0,
      (away_score - home_score) - spread_line > 0
    )
  ) |>
  count(fav_covered)
#   fav_covered     n
#         FALSE    15
#         TRUE      6
#         NA        1

Favorites covered 6 of the 21 games with a result either way; the NA is the one push, 1999_01_KC_CHI, where Chicago was a 3-point favorite and won by exactly 3. Across all 259 games of the 1999 season the favorite covered 47 percent, the favorite_cover_pct value in season-summaries.csv. Lines, covers, and the sign convention get a full treatment in the spread history guide.

The same three queries in data.table

data.table reads URLs too, with fread, and answers the same questions in its DT[i, j, by] syntax:

library(data.table)

games <- fread("https://jayjex.github.io/data-vault/data/nfl-games/sample.csv")
dim(games)   # 22 46

# top 5 by wins
games[, .(winner = fifelse(home_score > away_score, home_team, away_team))]
  [, .(wins = .N), by = winner][order(-wins, winner)] |> head(5)
#    winner wins
# 1:    DET    2
# 2:    JAX    2
# 3:    PIT    2
# 4:    ARI    1
# 5:    BUF    1

# dome vs outdoors
games[, .(games = .N, avg_total = mean(total)), by = roof]

# season 1999 only, joined to the summaries table
summaries <- fread("https://jayjex.github.io/data-vault/data/nfl-games/season-summaries.csv")
merge(games[season == 1999], summaries, by = "season")

fread downloads from the URL itself, and it decompresses .gz and .bz2 automatically if you ever feed it compressed exports. Which package wins is taste at this file size; at 7,548 rows both finish before you switch tabs.

NFL data in R questions

Does read_csv parse the NFL sample cleanly on the first pass?
Yes, with two things to expect. Scores, lines, rest days, and roof parse as numeric with the right values on the first pass, and the 6 dome games arrive as NA in temp and wind because the source file is blank there. The sample also carries 10 fully empty columns (gametime, nfl_detail_id, pff, ftn, the moneyline and odds columns), which readr guesses as logical NA; if you want them as character, name them in col_types.
readr or data.table for the full 7,548-row NFL file?
Both handle it without effort. 7,548 rows by 46 columns is small enough that any R loader reads it in under a second on ordinary hardware. data.table::fread is the faster of the two, runs multithreaded, downloads from a URL itself, and decompresses .gz and .bz2 automatically. readr::read_csv returns a tibble that pipes into dplyr with zero conversion. If you already live in the tidyverse, use readr; if you want raw speed or the compact data.table syntax, use fread.
Will the same R code run on the full 7,548-row NFL pack?
Yes, unchanged. The sample is the first 22 rows of games.csv with the same 46-column schema, so every read_csv, filter, group_by, and merge call here runs the same way on the full file, 1999 through 2026. Only the row count grows, and the odds columns that sit empty in the 1999 sample fill in from 2006 onward. The full pack ships with a data dictionary and SHA-256 checksums.
