NFL roster data: free sources, ID schemes, and a live ESPN API example

Player-level sources, tested 2026-09-07 · for the game-level table this site sells around, start with the games.csv column guide · pricing lives on the dataset pages, not here.

NFL roster data means one row per player per team per week: jersey number, position, status (active, practice squad, injured reserve), physical measurements, and the IDs that tie a player to other datasets. Three free sources cover it. The nflverse weekly rosters release ships one CSV per season, 2002 through 2026, with 36 columns and nine provider IDs per player. nfl_data_py wraps those files in one call, import_weekly_rosters(years). The ESPN site API returns the same rosters as JSON at site.api.espn.com, no key, which makes it the quickest way to check today's 53-man sheet.

An honest note on scope before the details: the dataset this site documents, the NFL Games & Betting Lines 1999-2026 pack, is game-level only. Its 7,548 rows are one per game, and the only player fields are the two starting quarterback names and IDs. There are no roster rows or per-player stats in it, and this page does not pretend otherwise. The three sources below are where player-level data actually lives, and the last section shows how far you can get joining them to game data, including where the join breaks.

In Python, skip the manual download:

import nfl_data_py as nfl
rosters = nfl.import_weekly_rosters([2026])
# 2,954 rows x 36 columns, same schema as the CSV above
kc = rosters[rosters["team"] == "KC"]
len(kc)   # 92 rows: 76 current players + weekly status snapshots

Schema notes worth knowing before you write a parser. id is the athlete ID and the only key that lines up with other datasets; it arrives as a string. height and weight are numbers (inches, pounds) while the display* twins are strings formatted for humans; parse the numeric ones. jersey is a string, so sort it as one. position.parent gives the unit (offense, defense, special teams) so you do not need the group structure to bucket players. status.type distinguishes active from practice squad and injured reserve. And the cut links array includes a per-player game-log URL, which is where ESPN exposes player week-by-week stats if you need them from the same API family.

Compared to the nflverse CSV, the ESPN response is thinner on IDs (one, not nine), thinner on history (current week only, no 2002-2025 archive), and thicker on presentation fields (headshots, slugs, display strings). Use it for current-state checks and quick scripts; use nflverse for anything you will re-run next season.

Joining roster data to game-level data, honestly

Player-level and game-level data use different ID schemes, and a join only works where a file carries both. Here is the map:

ID columnLives inMatches
gsis_idnflverse roster files, play-by-play, weekly and seasonal player statsthe standard join key across all nflverse player-level files
espn_idnflverse roster filesthe numeric athlete id in the ESPN API (verified below)
gsis (game)games.csv gsis columna game ID, unrelated to player gsis_ids despite the similar name
espn (game)games.csv espn columna game ID, not an athlete ID

The espn_id claim is testable, so we tested it. nflverse's 2026 weekly roster file holds 92 Chiefs rows with 60 distinct non-blank espn_id values; the live ESPN roster response returned 76 athlete IDs. The two sets overlap on 56 players (Travis Kelce 15847, Chris Jones 3044859, Harrison Butker 3055899, and so on, names matching on every overlap). The 4 misses are roster churn between snapshots, not an ID mismatch: new signings not yet in ESPN's group lists and vice versa. So the join rate on a matched-day snapshot is 56 of 60, and the general rule is that nflverse.espn_id == ESPN athlete.id.

What no join gives you, because the underlying rows do not exist in a game-level file: per-player usage inside a specific game. The team-season table counts team results; its only player references are the two starting QB IDs per game (away_qb_id, home_qb_id, which are gsis_ids and join cleanly to the roster's gsis_id column). To attach player stats to a game you need nflverse's play-by-play or weekly stat files, keyed on gsis_id, with the roster file as the bridge that maps gsis_ids to names and the ESPN API for current-week cross-checks. That is a three-file join, all free, and the honest state of the art without a commercial feed.

NFL roster data questions

Is there a free NFL roster CSV?

Yes. The nflverse-data project publishes weekly rosters as one CSV per season, 2002 through 2026, at github.com/nflverse/nflverse-data/releases/tag/weekly_rosters. The 2026 file is 2,954 data rows and 36 columns, with jersey number, status, position, and nine provider IDs per player including gsis_id and espn_id. In Python, nfl_data_py's import_weekly_rosters(years) pulls the same files as DataFrames. The ESPN site API also returns rosters as JSON, no key required.

Does the Data Vault NFL pack include player-level data?

No. The NFL Games & Betting Lines pack is game-level only: 7,548 rows in games.csv, one per game with team scores, spreads, totals, and weather. The only player fields are starting QB name and ID for each side. There are no roster rows, depth chart rows, or per-player stat lines in the pack. For player-level data, use nflverse's weekly rosters and stat files, or the ESPN site API.

How do I match roster players to game-level data?

Through the ID columns, and the two schemes do not overlap: roster files carry gsis_id (the NFL's Game Statistics & Information System ID, used across nflverse play-by-play and weekly stats) and espn_id (which equals the numeric athlete ID in ESPN's API). We verified the espn_id match on the 2026 Chiefs: 56 of the 60 non-blank espn_id values in nflverse's roster file appear among the 76 athlete IDs in the live ESPN roster response. Game files carry a gsis game ID and an espn game ID, which are different keys again, so game-to-player joins run through gsis_id in play-by-play data, not through the roster file alone.
