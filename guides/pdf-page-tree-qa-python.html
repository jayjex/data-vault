How to QA a PDF's internal structure in Python

Published 2026-09-10. Every output on this page is verbatim from runs on 2026-09-10 with Python 3.14.4, pypdf 6.18.0 and pdfcheck-mcp 0.1.1 on Linux. The two fixture PDFs ship with the pdfcheck-mcp repo under MIT.

Why stream counts lie

We shipped 13 product PDFs that were unreadable, and our QA passed every one of them. The QA counted stream objects and found plenty: each file carried healthy compressed content streams with real text operators. What it never did was look at the page tree, and the page tree is what a reader actually walks. In all 13 files the generator had written objects with a one-slot offset bug: /Kids pointed at a font object, every page dictionary's /Contents pointed one slot down the chain, and the last real page dictionary sat orphaned outside the tree. Viewers rendered blank pages. pypdf did not raise either; it quietly reported fewer pages.

This page builds the check that catches that class of bug. It walks the object graph the way a viewer does, runs four checks against the page tree, and prints a verdict. The code runs against two fixtures: a healthy 4-page PDF and the broken-wiring variant from the incident, so you can see what a pass and a failure look like with real numbers.

The page tree in one minute

A classic PDF is a list of numbered objects plus a cross-reference (xref) table giving each object's byte offset. The trailer names the root object, the root is the catalog, and the catalog names the page tree:

trailer
<< /Size 13 /Root 1 0 R >>
1 0 obj    << /Type /Catalog /Pages 2 0 R >>
2 0 obj    << /Type /Pages /Count 4 /Kids [6 0 R 8 0 R 10 0 R 12 0 R] >>
6 0 obj    << /Type /Page /Parent 2 0 R /Contents 5 0 R /MediaBox [0 0 612 792] >>
5 0 obj    << /Length 62 >> stream ... endstream

Four links matter. The trailer's /Root reaches the catalog, the catalog's /Pages reaches the tree root, the tree root's /Kids array lists the page dictionaries, and each page dictionary's /Contents points at the stream object holding the text. The /Count field claims how many pages the tree holds. A PDF renders when all four links hold; it breaks, without any object being visibly corrupt, when one of them points at the wrong numbered object.

The four checks

QA for the graph reduces to four questions, asked in order:

a. Kids resolve to pages. Every reference in /Kids must land on an object whose type is /Page. A font object, a stream, or an empty body in that slot means the tree itself is miswired.

b. Contents point at streams with ink. Every page's /Contents must reference a stream object, and the stream must carry at least one text-showing operator (Tj or TJ). A stream with no Tj is a blank page wearing a valid object number.

c. No orphan pages. Every /Type /Page object in the file must be reachable from /Kids. An orphaned page dictionary is a page no viewer will ever show.

d. Count matches reachability. The /Count claim must equal the number of pages actually reachable through /Kids. A mismatch is the cheapest possible summary that something upstream is wrong.

The walker, in Python

About 70 lines, standard library only. It parses the classic xref layout, builds an object-number to body map, and runs the four checks. Save as qa_page_tree.py:

#!/usr/bin/env python3
"""Page-tree QA for classic-xref PDFs: /Kids -> /Type /Page, /Contents -> stream,
orphan pages, /Count vs reachable. Same four checks as pdfcheck-mcp, in Python."""
import re
import sys

def load_objects(data):
    """Map object number -> body text, plus the raw file text, for a classic xref."""
    text = data.decode("latin1")
    sx = re.search(r"startxref\s+(\d+)", text)
    if not sx:
        sys.exit("no startxref: not a parseable PDF")
    if text[int(sx.group(1)):int(sx.group(1)) + 4] != "xref":
        sys.exit("compressed xref stream: outside this walker")
    objects = {}
    for m in re.finditer(r"(\d+)\s+\d+\s+obj\b", text):
        end = text.find("endobj", m.end())
        objects[int(m.group(1))] = text[m.end(): end if end != -1 else len(text)]
    return text, objects

def walk(data):
    text, objects = load_objects(data)
    body = objects.get
    problems = []

    trailer = re.search(r"trailer\s*<<(.*?)>>", text, re.S)
    if not trailer:
        sys.exit("no trailer dictionary")
    root = int(re.search(r"/Root\s+(\d+)\s+\d+\s+R", trailer.group(1)).group(1))
    pages_obj = int(re.search(r"/Pages\s+(\d+)\s+\d+\s+R", body(root, "")).group(1))
    pages_body = body(pages_obj, "")
    count_claim = int(re.search(r"/Count\s+(\d+)", pages_body).group(1))
    kids = [int(x) for x in re.findall(
        r"(\d+)\s+\d+\s+R", re.search(r"/Kids\s*\[(.*?)\]", pages_body, re.S).group(1))]

    # (a) every /Kids entry resolves to a /Type /Page object
    reachable = []
    for num in kids:
        if re.search(r"/Type\s*/Page\b", body(num, "")) and \
           not re.search(r"/Type\s*/Pages\b", body(num, "")):
            reachable.append(num)
        else:
            kind = re.search(r"/Type\s*/(\w+)", body(num, ""))
            problems.append("kids-not-Page: obj %d is /Type /%s"
                            % (num, kind.group(1) if kind else "none"))

    # (b) every page /Contents points at a stream object that has ink (a Tj op)
    for num in reachable:
        cm = re.search(r"/Contents\s+(\d+)\s+\d+\s+R", body(num, ""))
        if not cm:
            problems.append("contents-missing: page obj %d has no /Contents" % num)
            continue
        stream_obj = body(int(cm.group(1)), "")
        if "stream" not in stream_obj:
            kind = re.search(r"/Type\s*/(\w+)", stream_obj)
            problems.append("contents-not-stream: page obj %d -> obj %s (type %s)"
                            % (num, cm.group(1), kind.group(1) if kind else "none"))

    # (c) orphan pages: /Type /Page objects the /Kids array never reaches
    all_pages = {n for n, b in objects.items()
                 if re.search(r"/Type\s*/Page\b", b) and not re.search(r"/Type\s*/Pages\b", b)}
    orphans = sorted(all_pages - set(reachable))
    if orphans:
        problems.append("orphan-pages: %s" % orphans)

    # (d) the /Count claim matches the pages actually reachable
    if count_claim != len(reachable):
        problems.append("count-mismatch: /Count claims %d, /Kids reaches %d"
                        % (count_claim, len(reachable)))

    return {"count_claim": count_claim, "reachable": len(reachable),
            "orphan_nums": orphans, "objects_in_file": len(objects),
            "ok": not problems, "problems": problems}

if __name__ == "__main__":
    with open(sys.argv[1], "rb") as f:
        import json
        print(json.dumps(walk(f.read()), indent=1))

Three parsing details do the work. The xref check reads the byte offset in startxref and expects the keyword xref there; compressed xref streams are rejected instead of half-parsed, because a half-parse that reports ok is worse than a refusal. Object bodies are cut at the first endobj after each N 0 obj header, which is exact for classic layouts. And check (a) requires /Type /Page while rejecting /Type /Pages, because the tree root itself is also typed Pages-like and a naive match would pass a tree pointing at itself.

Run it on a healthy PDF

The first fixture is a real generated product page, 9,469 bytes, 12 objects:

python3 qa_page_tree.py healthy-checklist.pdf

Output, verbatim:

{
 "count_claim": 4,
 "reachable": 4,
 "orphan_nums": [],
 "objects_in_file": 12,
 "ok": true,
 "problems": []
}

Clean across the board: /Kids [6 0 R 8 0 R 10 0 R 12 0 R], all four slots are /Type /Page, all four /Contents references land on streams, no orphans, and the claimed /Count 4 equals the 4 reachable pages.

Next, cross-check with pypdf, which reads the file the way a reader does. One loop over both fixtures, no setup beyond pip install pypdf (6.18.0 here):

import pypdf

for path in ("healthy-checklist.pdf", "broken-wiring.pdf"):
    r = pypdf.PdfReader(path)
    page = r.pages[0]
    print(path, "| pages:", len(r.pages),
          "| size:", int(page.mediabox.width), "x", int(page.mediabox.height),
          "| meta:", dict(r.metadata or {}) or "{}",
          "| text head:", repr(page.extract_text()[:42]))

The run prints one line per file; the broken fixture's stderr warning belongs to the next section. The healthy line, verbatim:

healthy-checklist.pdf | pages: 4 | size: 612 x 792 | meta: {} | text head: 'Smart Contract Security Audit Checklist\n12'

4 pages, US Letter at 612 x 792 points, no metadata (common for generated files and not a defect), and a text layer that extracts. Both the graph and the reader agree.

Run it on the broken-wiring PDF

The second fixture is the incident shape: 1,458 bytes, 13 objects, built by a generator whose object-number arithmetic assumed a 3-font header and shifted every later object by one slot. Same command:

python3 qa_page_tree.py broken-wiring.pdf

Output, verbatim:

{
 "count_claim": 4,
 "reachable": 3,
 "orphan_nums": [
  13
 ],
 "objects_in_file": 13,
 "ok": false,
 "problems": [
  "kids-not-Page: obj 5 is /Type /Font",
  "contents-not-stream: page obj 7 -> obj 5 (type Font)",
  "contents-not-stream: page obj 9 -> obj 7 (type Page)",
  "contents-not-stream: page obj 11 -> obj 9 (type Page)",
  "orphan-pages: [13]",
  "count-mismatch: /Count claims 4, /Kids reaches 3"
 ]
}

Six lines, one per defect, and together they draw the whole miswiring. The /Kids array is [5 0 R 7 0 R 9 0 R 11 0 R]: slot one lands on the font object (obj 5), while the real page dictionaries (objs 7, 9, 11) got picked up as kids. Each of those page dictionaries carries a /Contents that points one slot down the chain, page 7 at the font, page 9 at page 7, page 11 at page 9. The fourth page dictionary, obj 13, never received a kid slot at all, so it is orphaned. And /Count still claims 4 pages because the generator counted what it meant to write, not what it wrote.

Now the reader's view of the same file, which is the part that makes stream-count QA dangerous:

Ignoring page tree entry that is not a dictionary: /Type
broken-wiring.pdf | pages: 3 | size: 612 x 792 | meta: {} | text head: ''

pypdf opens the file without raising, reports 3 pages instead of 4, extracts empty text, and moves on. The one warning it prints is a stderr note, easy to miss in a build log. A QA that only counted objects would see 4 content streams and 4 page dictionaries and pass the file. The graph is what fails, so the graph is what QA has to walk.

The same checks as a tool you can install

The walker above is the Python reading of the check that ships as pdfcheck-mcp, a free MIT-licensed MCP server on npm. It exposes pdf_qa for one file and pdf_batch for a directory, groups the defects into the four classes, and adds the ink check as a zero-Tj counter.   "orphan-pages=1 [13]",
  "count-mismatch claimed=4 reachable=3"
 ]

Same six defects, grouped into four classes with per-object detail. The response also carries the file path and a report object with the per-check tallies; the ok flag and problems list here are verbatim from the run. Install it free:

FAQ

What does QA on a PDF's internal structure check?

Four graph checks: every /Kids entry resolves to a /Type /Page object, every page /Contents points at a stream object that carries text-drawing operators, no /Type /Page object is orphaned outside the /Kids array, and the /Count claim matches the pages actually reachable. The walker on this page runs all four in about 70 lines of Python.

Why did my PDF QA pass but the pages render blank?

Because the QA counted stream objects instead of walking the page tree. A PDF can carry 24 healthy content streams and still be unreadable when /Kids points at a font object, /Contents points one slot off, and every real page dictionary sits orphaned outside the tree. We shipped 13 product PDFs in exactly this state and the stream-count QA passed all of them; pypdf reported the pages without raising, and viewers rendered blanks.

Does this page-tree walker work on every PDF?

It covers classic (uncompressed) xref tables, which is what most PDF generators write. Files with compressed xref streams are rejected with a clear message instead of a false pass, and encrypted files are out of scope. The same checks ship as the free npm package @jayjex/pdfcheck-mcp with a batch tool for whole directories.
