Weather data APIs for analysts: tested live

Published 2026-09-10 · every request below ran live from our test box on 2026-09-07 · outputs are pasted exactly as returned.

Analysts reach for weather data in three situations: today's numbers and the next two weeks, a historical record to backtest against, and long-run station data for a climate or research question. Commercial aggregators wrap all three behind one monthly bill. The free endpoints below already do the job, and each returned HTTP 200 with no API key when we tested it.

Live weather: Open-Meteo forecast API

Open-Meteo runs on documented models (GFS, ECMWF, ICON) and serves them without a key on a free tier of 10,000 calls per day for non-commercial use. One GET returns current conditions for any coordinate on earth. We first ran this endpoint for the public data APIs list; the schema has not moved since. The call:

curl -s "https://api.open-meteo.com/v1/forecast?latitude=40.71&longitude=-74.01&current=temperature_2m,wind_speed_10m"

The response, 372 bytes, pretty-printed for this page:

{
 "latitude": 40.710335,
 "longitude": -73.99308,
 "generationtime_ms": 0.032782554626464844,
 "utc_offset_seconds": 0,
 "timezone": "GMT",
 "timezone_abbreviation": "GMT",
 "elevation": 27.0,
 "current_units": {"time": "iso8601", "interval": "seconds", "temperature_2m": "°C", "wind_speed_10m": "km/h"},
 "current": {"time": "2026-09-07T15:45", "interval": 900, "temperature_2m": 24.8, "wind_speed_10m": 13.7}
}

24.8 °C and 13.7 km/h wind at Lower Manhattan, timestamped 2026-09-07T15:45. Two details analysts should notice. First, the API snaps your coordinates to its model grid: we sent 40.71, -74.01 and it echoed back 40.710335, -73.99308 at elevation 27.0 m, the cell it actually evaluated. Second, the current block is one slice. Add &daily=temperature_2m_max,temperature_2m_min&forecast_days=16 and the same endpoint returns 16 days of daily highs and lows in one call, which is usually what a forecast-driven report actually needs.

The historical weather API: Open-Meteo Archive

Forecast endpoints only see the future. For backward-looking work such as backtests, seasonality curves, and features for a model, Open-Meteo runs a second API at archive-api.open-meteo.com. It serves ERA5 reanalysis on daily and hourly steps, with most variables reaching back to January 1940, under the same no-key, 10,000-calls-per-day policy. Our test asked for one city, one full year of daily highs, lows, and precipitation, in local days:

import json, urllib.request

url = ("https://archive-api.open-meteo.com/v1/archive"
       "?latitude=40.71&longitude=-74.01"
       "&start_date=2025-01-01&end_date=2025-12-31"
       "&daily=temperature_2m_max,temperature_2m_min,precipitation_sum"
       "&timezone=America/New_York")
daily = json.load(urllib.request.urlopen(url))["daily"]

days = daily["time"]
highs = daily["temperature_2m_max"]
lows = daily["temperature_2m_min"]
rain = daily["precipitation_sum"]

hottest = highs.index(max(highs))
coldest = lows.index(min(lows))
wettest = rain.index(max(rain))

print(f"days={len(days)} mean_high={sum(highs)/len(highs):.1f}C")
print(f"hottest={highs[hottest]}C on {days[hottest]}")
print(f"coldest={lows[coldest]}C on {days[coldest]}")
print(f"wettest={rain[wettest]}mm on {days[wettest]}")
print(f"total_precip={sum(rain):.1f}mm")

The script's printed output:

days=365 mean_high=17.0C
hottest=40.4C on 2025-06-24
coldest=-16.7C on 2025-01-22
wettest=48.6mm on 2025-09-25
total_precip=1116.1mm

That is New York's 2025 in five lines: mean daily high 17.0 °C, a 40.4 °C peak on June 24, a -16.7 °C floor on January 22, and 1,116.1 mm of precipitation spread across the year. The raw response was 10,462 bytes with 365 rows; the arrays start at "2025-01-01" with a high of 11.0 °C and end at "2025-12-31" with 7.4 °C. One wrinkle: the archive resolved our point to grid cell 40.738136, -74.04254 near LaGuardia Airport rather than the forecast API's cell. ERA5 is a model on a roughly 9 km grid, so a "point" value is always the nearest cell. Pass timezone=America/New_York as we did, or daily boundaries follow UTC.

US official forecasts: NWS api.weather.gov

The National Weather Service's API (docs) needs no key, but it does want a User-Agent header that identifies your application; keyless requests without one get throttled first. Its structure is a router: you give the points endpoint a coordinate, it returns the forecast office and grid cell everything else hangs off. The call we made for Washington, DC:

curl -s -H "User-Agent: matchbook-labs-data-vault-test/1.0" \
  "https://api.weather.gov/points/38.8894,-77.0352"

The full response runs 3,921 bytes; these are the fields worth reading, values verbatim:

{
 "cwa": "LWX",
 "forecastOffice": "https://api.weather.gov/offices/LWX",
 "gridId": "LWX",
 "gridX": 97,
 "gridY": 71,
 "forecast": "https://api.weather.gov/gridpoints/LWX/97,71/forecast",
 "relativeLocation": {"city": "Washington", "state": "DC"},
 "timeZone": "America/New_York",
 "radarStation": "KLWX"
}

cwa LWX names the forecast office (Baltimore/Washington), gridId/gridX/gridY pin the model cell, and the relativeLocation block confirms the nearest place it resolved to: Washington, DC. The forecast URL is the next hop; fetch it and you get the official 7-day narrative for that exact grid cell. When a report needs the US government's numbers rather than a model aggregator's, this is the source to cite.

Climate research: NOAA NCEI station records

For anything you plan to cite in a paper, NOAA NCEI's Access Data Service returns daily summaries from the GHCN-Daily network of instrument stations. The endpoint is keyless. Station USW00014732 is LaGuardia Airport; our call asked for five days of daily max, min, and precipitation in metric:

curl -s "https://www.ncei.noaa.gov/access/services/data/v1?dataset=daily-summaries&dataTypes=TMAX,TMIN,PRCP&stations=USW00014732&startDate=2025-07-01&endDate=2025-07-05&format=json&units=metric"

The response, all 443 bytes verbatim:

[
{"DATE":"2025-07-01","STATION":"USW00014732","TMAX":"33.9","TMIN":"22.2","PRCP":"7.6"}
,{"DATE":"2025-07-02","STATION":"USW00014732","TMAX":"28.9","TMIN":"22.8","PRCP":"0.0"}
,{"DATE":"2025-07-03","STATION":"USW00014732","TMAX":"33.3","TMIN":"21.7","PRCP":"0.3"}
,{"DATE":"2025-07-04","STATION":"USW00014732","TMAX":"28.9","TMIN":"20.6","PRCP":"0.0"}
,{"DATE":"2025-07-05","STATION":"USW00014732","TMAX":"31.1","TMIN":"21.1","PRCP":"0.0"}
]

Legal JSON, but not the shape most parsers expect to see: one object per row, with the second row comma-prefixed after a newline. A pandas read_json or a quick regex over the commas handles it. The values themselves are what the instruments recorded: July 1 hit 33.9 °C with 7.6 mm of rain.

One quirk worth knowing before you build a request: ask this station for TAVG and you get rows with no value field at all, because LaGuardia reports TMAX/TMIN/PRCP but no daily mean, and the API stays silent about the gap. Check which dataTypes a station actually records before your script loops over a list of them. Many GHCN-Daily stations hold decades of readings, which is exactly what makes this the source for extreme-value analysis and trend work.

FAQ

What is the best free weather data API?
For most analyst work, Open-Meteo: one keyless platform serves current conditions, a 16-day forecast, and the Archive API with daily history back to 1940, on a documented 10,000-calls-per-day free tier. Inside the US, add the National Weather Service API for official forecasts and alerts and NOAA NCEI when you need station-level history for climate research. All three returned live data with no key when we tested them from our box on 2026-09-07.
Can I get historical weather data for free?
Yes, two ways. The Open-Meteo Archive API serves reanalysis data back to 1940 with no key; one request pulled a full year of daily highs, lows, and precipitation for New York in about 10 KB of JSON. NOAA NCEI serves station records from the GHCN-Daily network, also keyless on the endpoint we tested, and many stations hold decades of daily readings. Reanalysis covers anywhere on earth; station records carry the thermometer's actual readings.
Which weather API should analysts use for long-term US research?
NOAA NCEI for anything you plan to cite. Its daily-summaries dataset returns station observations such as TMAX, TMIN, and PRCP straight from instruments at stations like LaGuardia Airport (USW00014732), and the test call needed no key. Open-Meteo's Archive API works better when you need gridded data for arbitrary points or international comparisons. The National Weather Service API covers forecasts and warnings, not long-term records.
