ESPN CDN endpoints: 10 hidden URLs for scoreboard, schedule, news and standings, no key

Tool page · companion to the ESPN API in Python guide and the NFL data APIs comparison · every status code and output line below comes from a live curl run on 2026-09-10.

ESPN's site runs on public JSON endpoints that were never documented: site.api.espn.com for the display feeds, cdn.espn.com/core for page fragments, sports.core.api.espn.com for the reference graph. All of them answer plain curl with no key. Ten are below, each with its URL and one line of verbatim output, all hit on 2026-09-10. Swap the league segment (football/nfl) for basketball/nba, hockey/nhl, baseball/mlb, or football/college-football and the same shapes come back.

Each endpoint gets its verbatim run below. The scoreboard takes the most parameters, so it comes first with a cheat sheet.

1. Scoreboard: dates, limit, groups

Base URL, no params, on the Sunday of week 1 in the 2025 season:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard?dates=20250907"
# HTTP 200, 13 events; events[0].name = "Tampa Bay Buccaneers at Atlanta Falcons"

dates=YYYYMMDD pins the calendar day; the surrounding week's games come back with it. limit caps the events array, and groups filters to one competition group:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard?limit=2"
# HTTP 200, exactly 2 events (default response: 29 KB, capped: 6.5 KB)
curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard?groups=8&dates=20250907"
# HTTP 200, 8 events, all AFC: Bengals-Browns, Dolphins-Colts, Raiders-Patriots...

The group IDs are not listed anywhere official; they are the ids on the conference objects inside /apis/v2/.../standings (NFL: AFC 8, NFC 7). Full NFC side, groups=7: 7 events. Other scoreboard params that answered on the checked date: seasontype (1 preseason, 2 regular, 3 postseason) and week. groups=28 or 29 still returns 200, but with zero events, so a 200 alone is not proof a group id means anything.

2. Full-season schedule from cdn.espn.com

The site API's scoreboard returns one week at a time. The CDN fragment service returns the whole season in one call. Bare cdn.espn.com/core/nfl/schedule returns HTML; append xhr=1 and it returns JSON:

curl -s "https://cdn.espn.com/core/nfl/schedule?xhr=1&dates=2026"
# HTTP 200, 261 KB; content.schedule keys = ["20260909","20260910","20260913","20260914"]
# content.schedule["20260913"].games[0].name = "Tampa Bay Buccaneers at Cincinnati Bengals"

The games sit under content.schedule, one date key per game day, and each date's games list carries the same event objects as the scoreboard feed. The default window is the current week; a dates=YYYY season parameter widens it, and individual dates work here too.

3. News feed

The least-known site API path: a clean article list with headlines, links, images, and publish dates. limit works here as well:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/news"
# HTTP 200, 6 articles; articles[0].headline = "NFL Week 1 betting: Odds, lines and totals for every game"
curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/news?limit=2"
# HTTP 200, exactly 2 articles

Sports swap the same way: football/college-football/news?limit=1 returned a Pitt upset headline on the checked date. Each article carries published, links.web, and an images array.

4. Standings

Note the version bump: standings live under apis/v2, not apis/site/v2:

curl -s "https://site.api.espn.com/apis/v2/sports/football/nfl/standings"
# HTTP 200, 157 KB; children = ["American Football Conference", "National Football Conference"]

Each child conference carries its group id (AFC 8, NFC 7), which is where the scoreboard's groups values come from. Appending ?groups=1 here changes nothing: standings accepts the param but always returns both conferences.

5. One-game summary

Box score, scoring drives, leaders, injuries, and odds for a single event ID. Event IDs come from the scoreboard response:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/summary?event=401772830"
# HTTP 200, 452 KB; header shows Atlanta Falcons 20, Tampa Bay Buccaneers 23, status Final

That was the week 1 2025 Falcons-Buccaneers opener, and the top-level keys include boxscore, drives, leaders, injuries, broadcasts, and againstTheSpread.

6. Team schedule

The per-team path from the roster endpoint, with schedule at the end:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/nfl/teams/kc/schedule"
# HTTP 200, 240 KB; 17 events; events[0] = "Denver Broncos at Kansas City Chiefs", 2026-09-15T00:15Z

7. Rankings (college football)

NFL has no rankings endpoint; the path 404s for football/nfl. College football returns every poll in one call:

curl -s "https://site.api.espn.com/apis/site/v2/sports/football/college-football/rankings"
# HTTP 200, 645 KB; polls = ["AP Top 25", "AFCA Coaches Poll", "FCS Coaches Poll", ...]
# AP Top 25 first four: Ohio State, Oregon, Georgia, Notre Dame

8. One athlete by numeric ID

The core API serves one flat, fast record per athlete. The numeric ID is the same value as nflverse roster files' espn_id column, verified in the NFL roster data guide:

curl -s "https://sports.core.api.espn.com/v2/sports/football/leagues/nfl/athletes/15847"
# HTTP 200, 4.7 KB; displayName = "Travis Kelce", position = TE

9. Team directory with $ref links

The core API's team list is paginated and link-based: each item is a $ref URL you fetch separately. That makes it the reference graph's front door:

curl -s "https://sports.core.api.espn.com/v2/sports/football/leagues/nfl/teams?limit=32"
# HTTP 200, 3.7 KB; count=32, items = $ref URLs under .../seasons/2026/teams/{id}

10. Soccer standings table

The same CDN fragment service covers every ESPN league, soccer included. The Premier League table in one call, xhr=1 again required for JSON:

curl -s "https://cdn.espn.com/core/soccer/table?league=eng.1&xhr=1"
# HTTP 200, 2.6 MB; eng.1 = Premier League, full standings JSON

Curl notes for every call

Plain curl or any HTTP client works: no key, no account, no special headers, same as the scoreboard in the ESPN API in Python guide. Three habits keep the endpoints happy: a --max-time or client timeout on every call, caching responses you already fetched, and backing off instead of looping retries. There is no published rate limit, and hammering an undocumented feed is how undocumented feeds get shut.

Endpoint coverage so far on this site: rosters in the NFL roster data guide, the scoreboard and teams walkthrough in the ESPN API in Python guide, and the wider source comparison, including the 401 that api.nfl.com returns to unauthenticated calls, in the NFL data APIs guide.

ESPN CDN endpoint questions

Is the ESPN CDN API free?
The public endpoints on this page cost nothing to call. All ten URLs answered plain unauthenticated curl with no key, no account, and no special headers on 2026-09-10. These are the same feeds ESPN's own site and apps load, served from site.api.espn.com, cdn.espn.com, and sports.core.api.espn.com. ESPN sells licensed developer feeds separately; what the site serves for free is what is documented here.
Is the ESPN API documented?
No. None of the endpoints on this page have a published schema, a versioning promise, or a stated rate limit. They power ESPN's own web properties and stay up because ESPN's pages depend on them, which has kept them stable for years, but ESPN can change field names, nesting, or availability at any time. Treat the endpoints as a bonus, keep timeouts on every call, and cache responses instead of re-fetching in a loop.
Can I use ESPN API data in my app?
For a hobby project, a prototype, or personal analysis, the feeds behave like any public JSON endpoint. For anything commercial, these endpoints are undocumented and carry no reuse terms, so there is no permission to republish their content at scale. The safer route for production is a pinned, licensed dataset: the NFL Games & Betting Lines pack on this site ships 7,548 games from the nflverse releases under CC BY 4.0, with a clear credit line and checksums.
